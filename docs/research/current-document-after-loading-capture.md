## Smallest grounded discriminator

The missing measurement is whether the exact retained captured window/content
root contains the unique eligible reader-owner structure already established by
[retained reader wiring](reader-scene-selection-wiring.md):
DocumentView.ToolSettings belongs to DocumentView; SceneViewsRoot is visually
parented through DeviceSceneView to that same reader. Owner/window/visibility and
uniqueness must correspond to the captured window, with change/absence/ambiguity
refusal. This is structural reader-domain correspondence, not document identity.

An absent reader structure in a complete bounded same-window domain would support
only that sampled domain's non-reader finding. A present eligible structure would
distinguish a reader-containing window from an unclassified loading window, but
would still not prove that grabWindow returns its current document pixels.
No-anchor/cap-incomplete/changed-domain results cannot select another window or
prove global document absence. Prior2ef census and d1 capture have different
candidate identities and no same-window/time join; combine neither as such proof.

The existing `tools/reader_metadata_census.h` is a bounded, metadata-only
structural diagnostic: it checks anchors, ownership and declared readable
property/type domains without application VALUE reads. It independently selects
the focused window; it is not already a capture-window-bound bridge. Its entry
does not qualify document/page values or render readiness. Any future same-window
observation would first require an exact reviewed correspondence/entry contract;
this assessment changes no source, traversal limits or operation authorization.

identifies the explicit DeviceSceneView.sceneView/document/pageId and reader
document/currentPageId/sceneController consistency relation. Its owned selector

execute application getters/bindings. Owned-QML success does not qualify native
access, ownership, lifetime or bounded side effects. No such native read is

## Public Qt limits and next evidence prerequisite

[Qt6.10.3 focusWindow](https://doc.qt.io/qt-6.10/qguiapplication.html#focusWindow)
selects the window receiving focus events.
[isSceneGraphInitialized](https://doc.qt.io/qt-6.10/qquickwindow.html#isSceneGraphInitialized)
reports scene-graph initialization, and
[frameSwapped](https://doc.qt.io/qt-6.10/qquickwindow.html#frameSwapped)
reports presentation queuing. Inferring document readiness from any of those
graphics/focus surfaces is unsupported by their semantics. The existing pinned
[vendor-path assessment](vendor-frame-signal-applicability.md) also leaves active
backend/image-store/content correspondence unresolved. Identical loading-image
hashes alone do not distinguish an unchanged scene from retained/cached pixels.

The next source decision therefore needs same captured-window reader-structure
correspondence, followed separately by an exact supported current-reference
observation and its document/page/owner/lifetime closure. That specifies the
missing discriminating evidence; it selects no payload change or operation.
Do not substitute another signal/count/sleep, backend selection/private getter/
offset/hook, forced render/input, menu automation, native opening, clock extension,
new build/nonce, held/spent replay or broad matrix. Main alone selects any later
independently reviewed permitted observation. Prior insertion/ink/reopen and d1
capture milestones remain; useful current-document capture remains unqualified.

## October 15 follow-up: same-grab measurement obtained

The independently accepted [7a4 actual observation](../experiments/capture-window-reader-structure-result.md)
supplies the exact captured-window/root measurement proposed above. Both samples
visited 35 objects with zero DocumentView.ToolSettings and SceneViewsRoot anchors,
ending at anchor-uniqueness with application-thread/current-window true. Neither
sample reports cap or context refusal. Downstream owner/metadata/page checks were
unreached. This finding concerns only each sampled reachable domain; it does not
prove global absence or stable node identities across the grab.

The published metadata helper counts anchor names while traversing the bounded
union of QObject children and visual childItems, before eligibility, visibility,
enabled state and reader-owner checks. It does not silently filter hidden or
unfocused anchors out of that name count. The retained DocumentView notepage
predicate gates focus, not this traversal. Therefore hiding/focus alone would
not explain zero anchors IF the exact pinned reader definitions were instantiated
and reachable in that sampled root. Whether those conditions actually held is
unestablished; no runtime component role or causal diagnosis follows.

The next missing discriminator is the captured window's semantic role joined to
the actual reader-component creation/instantiation and containment path. The
retained node 92/node 94 wiring establishes reader-internal relationships, not the
application-root/loading-to-DocumentView creation condition. The retained
registration-through-64 descriptor index is not a runtime component join. Main's
narrow retained-local lookup found no established creation-condition artifact;
other retained routing/overview components do not close this gap. No new resource
extraction or application VALUE read was performed for this assessment.

There is consequently no supported producer repair or implementable new precode
selected here. An exact retained parent/application-root creation path with
provenance would be useful source evidence, followed separately by a justified
runtime correspondence contract if supported. Another signal, count, sleep,
larger cap, speculative getter/private offset/hook, forced rendering/input or
native opening cannot substitute for that evidence. Native observe_page remains
NoNativeAdapter; loading plus absent anchors cannot become NoDocumentOpen.
Prior insertion/ink/reopen and normal capture milestones remain credited.
