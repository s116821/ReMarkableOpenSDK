## Passive condition and decision

The new `reader_insertion_condition` owns its frozen strings and computes facts
for a middle, last or single-page source. It checks source/count/right neighbor,
effective requested ID, active span and a separate bounded full-tree absence
result. A full-tree collision outside the active vector refuses. The actual tree
count is distinct from active count; sentinel roots, malformed spans/pointers,
changed final headers, callback exceptions and reentry at all eight callback
positions are covered. Last-page cases perform no right-neighbor lookup.

Its fixtures inject original array/search/equality/tree models using opaque
32-bit addresses and explicit caller assertions. They do not execute the native
find or establish native tree integrity. No `operator new` occurred while
observing; source review separately checks no QString copy/detach, GUI, I/O or
locking. The valid finite-tree and original lock/owner assumptions remain
external. `matched` grants neither native authority nor insertion permission.

`reader_insertion_forward_decision` requires lock-free state storage. Exactly one
pending-to-forward/cancel/reject transition wins. Ordered and actual competing
threads check cancellation cannot revoke a committed forward and competing
dispatchers cannot both win. This primitive performs no insertion, dispatch,
clock, allocation, I/O or callback. Later cancellation requests remain separate
Core facts.

## Optional Core and unchanged default

`Policy::NegativeOnly` remains the default with the original frozen predicate.
`ForwardIfCurrent` requires the separate frozen condition/callbacks and refuses
mixed forms, missing calls, mismatched target or a post-rejection mutex probe.
The current startup/coordinator does not select this policy.

All earlier 61 normal Core results / 642 checks remain raw-JSON identical, with
the same 17 fail-stop classifications. Thirty-nine new cases add 745 checks.
They exercise real owned ARM interception/unwind, one unchanged-argument forward,
middle/end/single/borrowed cases, bad conditions/collisions, early cancellation,
post-commit cancellation/deadline, original inner/outer-tail exceptions, missing
inner calls, duplicate/untracked interference and malformed registrations.
The owned original inner is deliberately a no-op: this proves control flow,
not page insertion.

Committed outcomes record inner and outer return separately. Errors after
commitment require reconciliation rather than a private rejection or retry.
An in-flight snapshot reads only the atomic decision and returns conservative
unknown/reconciliation facts, without racing unfinished plain outcome fields.
Review caught two initial gaps before compilation: late cancellation/interference
after terminal publication did not project unknown, and a normal outer return
without an inner call omitted outerReturned. Both were corrected and covered.

The first default-coordinator regression driver omitted the required bridge
`.cpp` from its frozen export; all four compile failures and the driver remain
preserved. R2 adds that input only. No SDK source change repaired that harness
error; all four default fixture/production-branch checks then passed.

compareStrings export/GOT admission only when requested before application main.

the complete tree-header storage without reading tree values on the GUI thread.

it does not cast that carrier over the native header. Wrong/unselected receivers
refuse. Native owners must remain retained by the caller.
