## Implemented behavior

NavigateIdentityCapture is appended to the existing enum. Existing modes, schemas
and publishers retain their behavior. The new mode requires canonical expected
document/page/index/count and matching fixed legacy fixture navigation. It consumes
one request, allows one existing opening and its5s queued opportunity, and clamps
the synchronous helper to20s and the remaining original30s operation/90s setup
budget. It creates no page and installs no insertion hook.

The Entry pins its admitted window/root/engine, owns the output files independently
of Entry lifetime and constructs a local Sink before the helper. Borrowed Sample
contexts fully unwind before file publication. Before committing an image it
checks the complete positive helper conjunction, claim consumption, both ready
identity joins, dimensions/quotas and the actual Sink byte count/hash.

Publication uses a distinct limited permission after observation is disarmed:
terminal state does not revive an old Sample guard. Fresh checks retain original
deadlines, root/request/incarnation, cancellation/restoration and GUI context.
Shutdown suppression remains sticky even after the request becomes terminal.

The file primitive duplicates the private root and pins each written inode with
O_PATH before closing its writable FD. Exclusive link/unlink commits verify
expected identities and link counts; image pin lifetime covers both commits.
One failed/reentered/revoked attempt cannot be retried. Partial files and uncertain
two-link states remain forensic. Pins prevent inode reuse from masquerading as the
closed original; they do not establish byte immutability or an atomic pair.

## Reproduced problems and repairs

An actual close/unlink/recreate control reused the original inode with equal coarse
metadata and passed the predecessor's seal. Keeping an O_PATH pin prevented that
reuse and caused refusal. The raw predecessor and repaired runs remain preserved.

Source review also found incomplete validation of a helper-positive result before
image commit. The final Entry checks the full conjunction and actual Sink facts.
An early review memo raced that fix and recorded the corrected source digest while
describing its predecessor; the final review explicitly corrects that provenance.

A separate actual owned replay delivered aboutToQuit during publication with
closingDown stillfalse. The predecessor published an accepted image pair despite
the signal. Moving sticky suppression before the terminal early return fixes that
path; the final matrix verifies all five publication phases and helper unwind.

Consumer review reproduced oversized numeric handling and PNG false positives
that Pillow alone accepted: late/duplicate palettes and an out-of-range indexed
pixel. The validator now bounds numeric bindings, validates palette placement and
uses an explicitly limited static truecolor RGB/RGBA8/16 profile. Indexed/gray
images and zTXt/iTXt/iCCP ancillary metadata are refused without rewriting originals.
CRC, exact complete deflate/scanlines, full local decode, dimensions and original
SHA/size must agree. The reported capture storage size is not a total decoder
memory guarantee.

Initial Entry R1 failed because a linked CPP was missing from the private export
list. R2 reached the new controls but failed a wrongly initialized default-mode
fixture. R3 passed its matrix but preceded the discovered late-quit repair. Those
runs and the first quit replay's CRLF shell-launch failure remain preserved; only
R4 qualifies the final Entry source.
