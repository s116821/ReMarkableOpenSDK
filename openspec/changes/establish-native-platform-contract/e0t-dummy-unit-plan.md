## Cleanup and final receipt

### Finite writable-transaction and cleanup preparation

Keep the live writer's command slot serialized through reconciliation, but distinguish its process-held lock from the durable unresolved write intent. Recovery after writer death may acquire the released lock and issue a fixed read-only query while preserving that intent; this is not permission to repeat the write. Before any takeover fork, verify the old writer's complete owned cgroup and exact command child are gone, with no pre-exec child able to publish later. An external writer needs an equally concrete process-tree containment proof; PID/EOF alone is insufficient. If a surviving/unknown command cannot be bounded, remain failed/unknown without exceeding the process budget.

The proposed cleanup phases, all inside the existing 30-second cleanup window, are:

1. Atomically latch transaction closed under the publication fence; reject every future case advance/start. Identify the sole cleanup owner and preserve unresolved intent, old process/job records and evidence. Finish old command-exit proof before borrowing the slot. Source-owned starts are fenced; this does not by itself cancel manager jobs or automatic restarts.
2. Query the exact owned units/jobs and manager instance with bounded output. Reconcile any retained write against this snapshot and fixed allowlisted actions; no unknown start/stop resend. Preserve the original unrelated job identities (including those present before E0T); do not infer ownership from a new ID alone.
3. If pending owned jobs require cancellation, one bounded batch may contain at most 12 distinct positive uint32 IDs, each freshly correlated to an exact owned unit/type in the same manager instance. A zero-length batch emits **no command**; bare cancel is unrepresentable. This is a proposed extension of the single-ID T5 transport requiring exact parser/operator review. Snapshot-to-cancel is not atomic: sole-writer fencing and finite dummy dependencies narrow the race, but changed identity, unexplained replacement, manager restart or unresolvable output is failed/unknown. Never count row disappearance as a successful cancellation result.
4. Issue at most one fixed nonblocking stop request listing the 11 owned case/worker/handler units, excluding experiment cleanup. The already reviewed effective dependency graph must show that its transaction cannot stop a real vendor unit or invoke a real handler. An explicit stop must also quiesce the claim unit's direct-restart activity; a closed file alone cannot do that. Record the request as indeterminate until fresh evidence establishes its result. A lost reply is reconciled, not blindly retried.
5. Observe bounded fresh job/unit state and exact process/cgroup identities until all case units are inactive, all their cgroups empty, and no owned start/restart/writer can resurrect them. Inspect unexpected handler jobs as owned effects to reconcile, not a reason for an unbounded cancel loop. A replaced/running job, live descendant or ambiguous late request keeps cleanup failed/unknown. Preserve evidence and files if these conditions cannot be established.
6. Only after quiescence may the operator collect bounded evidence, remove exact owned case artifacts/fragments with ownership checks and perform the reviewed reload. Keep experiment cleanup's files/process until its remaining duties are discharged; the independent operator performs its final exit/removal and final verification. Compare original service configurations, identities and unrelated jobs with the recorded baseline. Do not remove the only remaining recovery actor to make a cleanup report look empty.

Freeze a command-count/time allocation, not merely a 30-second loop. A preparation target is one bounded initial query group, one optional cancel batch, one stop batch, at most three bounded verification query groups, and one reload; expand a query group into its exact CLI invocations and account for each 2-second command bound plus file/process checks. Reject a packet whose worst-case sum leaves no explicit cleanup margin. No repeated stop/cancel on a timer. CPU2 is still an unqualified candidate for the entire cleanup process, not two seconds per command; profile the complete code path or propose a revised role row before freeze. A 15-second worker alarm must not be inherited as the experiment cleanup lifetime: use role-specific bounds tied to the original 180-second trigger/210-second final deadline, with no renewal. Deadline expiry records failed/unknown and never implies cleanup or actor exit succeeded. An operator/collector outside this lifetime remains separately bounded and included in the resource table.

These phases authorize implementation preparation only. Batch mutation encoding, manager-job reconciliation, final cleanup ownership and exact resource/deadline evidence must pass independent review and coordinator packet assessment before any device effects. T5 remains the deliberate single-job cancellation case; cleanup batching adds no ninth test or broader cancellation authority.

Concrete schedule candidate for implementation review: initial jobs+states (2 calls), optional cancel (1), stop the 11 case units (1), one jobs+states verification group (2), stop experiment cleanup after its duties are discharged (1), jobs+states verification before removing its files (2), final reload (1), and final jobs+states verification (2): at most 12 CLI calls. At 2 seconds each, reserve another 2 seconds for old-writer/child exit, 2 seconds for bounded file/evidence work and **2 seconds explicit margin** within the 30-second window. One intermediate verification group is sufficient for a conservative experiment: a still-pending job/live cgroup/ambiguous snapshot returns failed/unknown, without polling, retries or additional calls. This schedule supersedes the earlier three-group sizing example for this implementation candidate, not the evidence requirements.

The full command bound must include spawn, actual child exit, complete bounded output, parsing and bookkeeping, or charge their extra time explicitly; the same time cannot be counted twice as available margin. Direct identity/cgroup/file reads, collection and fragment/root removal must fit their allocated work budget. No hidden shell utilities, SSH reconnects or additional manager queries. Each path, including early refusal and cleanup-actor termination, must have a source-derived bound and actual evidence before freeze. Numbers remain unqualified until then. If cleanup is still required, do not stop its actor to force the schedule to finish; retain failed/unknown duty without claiming an authorized deadline extension.

Combined job observations may cover the 12 owned names plus the exact baseline-only names, using disjoint observation/action types; state observations may cover 12 owned plus three originals only if the complete schema fits the reviewed 4096-byte ceiling. Overflow refuses without truncation. The post-reload proof is absence of owned fragments/startable definitions, active processes and pending jobs, with expected not-found/inactive results—not disappearance of every internal unit object, because querying an absent name can produce a not-found object. Original-unit continuity and unrelated-job observations remain separate. Final helper/root removal is performed only by the surviving external operator after all helper users have exited; account for any operator executable location or evidence path that remains in use.

Latch the transaction closed; resolve/cancel only its jobs; stop exact owned units; verify their cgroups/processes empty; preserve bounded evidence on the host; remove only exact owned fragments and files whose ownership still matches; reload once; verify no owned loaded/startable units or jobs remain. Keep the cleanup actor available until these duties are discharged; its final exit/removal is performed by the independent operator and verified. No reset-failed on unrelated units, global job cancellation or reboot. An unresolved cleanup duty remains explicit and forbids E1.

Before/after and between cases check original xochitl/Reader/rm-sync PID/start identities, state, effective configuration hashes, mappings relevant to absence of new preload, and relevant job identities. Any original change terminates the experiment; record it without claiming E0T caused or repaired it. Preserve unrelated jobs rather than requiring the entire manager queue to be empty. Original physical UI responsiveness may remain unverified; no human participation is required.

## Freeze checklist and evidence limits

The runnable packet must contain exact source/artifact/unit hashes, all names/paths, original baseline/profile, complete commands/property expectations, actor ownership, case barriers, resource/time bounds, failure/cleanup routes and consumer Docs counterpart. Those artifacts are not yet supplied by this proposal. Main obtains independent source/operator review and coordinator approval of that exact packet before any device write/start. A replacement build, changed case or changed profile requires a new packet.

E0T can establish dummy-unit behavior under the actual vendor manager. It cannot establish xochitl shutdown/persistence, rm-sync tolerance, native GUI behavior, loader safety, cold boot or production recovery. The observed rm-sync BindsTo/PartOf and reverse activation remain E1 gates. Source basis: coordinator's explicit proposal request, inspected configuration receipts, upstream parser/source and failed host-manager isolation. All dummy cases and bounds here are proposed, not executed.
