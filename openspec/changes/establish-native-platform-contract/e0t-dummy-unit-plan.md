# E0T: finite device systemd comparator using owned dummy units

Status: proposal/preparation only. Coordinator review of the frozen source/artifact/operator packet is required before staging or starting anything. Main is the sole operator. This addresses the host's unavailable live systemd manager; it does not relax E1 or qualify xochitl behavior. No wider host container privileges are requested.

## Scope and ownership

Use the actual tablet manager with original harmless helpers and fake units only. Preserve real xochitl, Reader Buddy, rm-sync, their processes and every vendor/user configuration byte. No XOVI, preload, native payload, document/account access, drawing/input, real failure/reboot handler, firmware/boot settings or global manager-environment changes. The names of real services appear only in the operator's fixed read-only continuity checks, never in dummy unit dependencies, helper action targets or cleanup lists.

Generate one 128-bit transaction nonce on the host, freeze it in the reviewed manifest, and refuse if any corresponding name/path exists. Use exact names `buddy-e0t-<nonce>-<role>.service` with at most 12 enumerated roles; a role is not an arbitrary argument. Files live under one root-owned mode-0700 `/run/buddy-e0t-<nonce>/`; the at-most-12 unit fragments are exact regular files under `/run/systemd/system/`. No directory shadowing or drop-ins on existing units. Paths, inodes and initial absence belong to the manifest; no symlink traversal or wildcard deletion. All payloads and evidence are volatile. The approved packet lists every final path, not a shell-generated unconstrained prefix.

Do not put dummy units in a boot target, enable them, attach them to real vendor units, or change global limits. Disable default dependencies in the fake units and inspect actual implicit manager dependencies; normal system.slice accounting is not a reference to a vendor application. Empty OnFailure cannot clear inherited handlers: an unexpected generic handler/action causes refusal before **any** dummy start, including the cleanup actor.

The path manifest enumerates every owned unit fragment **and** T1's exact owned `.service.d` parent directory and drop-in file, plus the session directory and each helper/evidence file. Record expected initial absence and ownership for each created parent separately. Cleanup removes a created parent only when its identity still matches and it is empty; never recursively delete a systemd directory. Existing `/run/systemd/system/` is not owned. The drop-in belongs only to T1's uniquely named fake unit, never a generic or prefix directory. These files do not permit additional units beyond the 12-unit cap.

Accepted preparation allocation: cleanup, controller, guard, stock, fail-a, fail-b, claim, norestart, separate, notify, barrier and queued are the 12 roles. T1 uses norestart as its failing worker with the owned drop-in and both fail-a/fail-b handlers. T2 may reuse that unchanged unit for its no-restart comparison and must expect both markers. This avoids a per-case reload; it does not combine two runs into one observation. Give each case a fresh run identity and disjoint bounded marker records; resolve prior jobs, processes and handler completion before reuse. A stale marker or cached unit result cannot satisfy a later case. The frozen packet must account for per-unit rate limits across reuse and refuse exhausted headroom rather than reset unrelated failure state. Fixed role names do not by themselves prove the concurrent helper/task limits.

## Frozen artifact and property gate

Main supplies original helper source, reviewed operator source, exact commit and SHA-256 for each target ELF/script/unit/manifest. Compile ARM32 hard-float against satisfied target imports; prefer a small C helper without Python, Qt, shell-command interpretation or dynamically selected executables. Fixed modes may hold on an owned pipe, send bounded systemd notify messages, exit with a chosen fixture status, append a bounded marker, and restore owned dummy state. All reads/writes use owned paths except read-only process identity and the manager notification socket supplied to that helper. No arbitrary command option or remote shell API. Runtime helper identity includes nonce, PID/start identity and mode; repeated PID alone is insufficient.

Before a manager reload, snapshot relevant effective properties/unit hashes and existing job IDs for the three original services. Refuse unrelated configuration drift that would make the reload apply unknown changes. A reload is a manager-wide action, so include it explicitly in the reviewed packet; it is not permission to change settings or reexecute PID1. After staging and one reload, inspect every dummy's effective fragment/drop-ins, ExecStart/stop/post commands, all dependency/action targets, user/group, cgroup, environment/preload, restart/start-limit/job/stop/runtime/watchdog settings and limits. Require exact allowlists and unchanged originals. Any mismatch aborts before start and removes only staged owned files through the reviewed cleanup path.

The packet must also account for generic and dash-prefix drop-in lookup for the chosen names; checking only service.d is insufficient. No dummy may inherit a vendor handler or unexpected ExecStartPre/Post/ExecStopPost. Prove the harmless marker handlers' complete effective commands before a failure case. Never invoke a handler merely because its name looks owned.

Cgroup membership remains useful for observation, but MemoryMax/TasksMax cannot be claimed as enforced. Coordinator directed preparation of the controls below as a possible equivalent for this finite dev test. The former mandatory cgroup-enforcement recipe is superseded for design; execution still refuses until exact source/artifact review demonstrates these replacement controls. No controller/kernel/global service changes are permitted.

Retain 12 roles, at most 8 concurrent helper/command processes and 16 tasks, 16 MiB staged files and 256 KiB evidence. These concurrency maxima are **program-bounded and observed**, not a kernel aggregate task guarantee. The previous 8 MiB-per-process/64 MiB arithmetic is an initial sizing target, not an enforced resident-memory aggregate or a demonstrated loader-compatible value. Freeze an explicit numeric per-artifact limit table from measured mappings and justified headroom; if it cannot keep the workload small, reduce concurrency first or submit a revised packet before execution. Never silently raise limits during a run. No busy loops, network or core dumps.

## Independent cleanup and event protocol

The cleanup actor is a separate owned unit outside the controller/worker cgroups. Start it only after its effective-property gate passes, verify its own start identity and nonce-bound acknowledgement, then allow case starts. It owns the immutable list of unit paths/job identities and an expiring lease. Controller loss triggers bounded cleanup; cleanup-actor loss makes the surviving controller stop the experiment and run the same idempotent cleanup. Do not test simultaneous loss in this packet or add recursive watchers. Self-exit limits on dummy workers bound leftovers but do not count as a cleanup receipt.

Separate roles explicitly: the experiment-wide cleanup actor and operator remain outside every case fault target; case-specific controller, guard and workers have distinct frozen unit/process identities. T6 kills only the case controller: its case guard owns the recovery under test, while experiment-wide cleanup retains eventual cleanup duty. T7 kills only the case guard: its surviving case controller owns recovery under test, while experiment-wide cleanup again retains duty. Neither case deliberately kills the experiment-wide cleanup actor. Its unexpected loss aborts all cases and transfers final cleanup to the surviving operator/controller through the reviewed protocol. A cleanup intervention cannot turn a failed case into a passing recovery result. The frozen role/concurrency table must count both experiment-wide and case actors, helper children and temporary command processes against the existing 12-unit, 8-helper and 16-task maxima; revise before freezing if the implementation cannot fit.

Use owned pipes/socket events and manager job completion records as barriers; sleeps are only watchdog deadlines. Job IDs must be correlated with transaction/unit identity before cancellation; preserve all preexisting unrelated jobs. On a lost start reply, query the exact owned unit/job and reconcile, never resend the start blindly. A restore receipt requires no outstanding start writer/request/job capable of recreating a dummy, all owned workers gone, and exact owned-state results. Runner cleanup after a failed case is recorded separately from the recovery under test.

### Actor protocol required before operator freeze

1. The experiment cleanup actor is transaction-scoped; a case controller/guard/worker is case-scoped. For the proposed immutable `role current` unit command, the helper opens and validates the owned case record once at invocation, snapshots its case/generation, and never changes identity by rereading it. Every handshake/marker includes transaction, case, actor role and actual process start identity. Only the operator advances the case after all previous case workers, command children, handlers and accepted jobs are terminal. Long-lived experiment cleanup is excluded from case advance but cannot issue case commands using stale authority.
2. Arm experiment cleanup first. For each case, record the controller and guard identities, establish both acknowledgements and the dummy baseline before enabling publication. An unacknowledged actor is not protection. The immutable action allowlist identifies exact case units and paths; a case byte cannot choose arbitrary commands or target the experiment cleanup actor.
3. Permit only one case command subprocess at a time. Before spawning, record its intended fixed operation/target and generation; while alive retain its OS handle/start identity. Record accepted manager job identity before acknowledging completion. A crash between request submission and recording leaves an unknown outcome to reconcile against the exact owned unit; it never authorizes a duplicate start. Keep a separate slot for experiment cleanup, with total worst-case task accounting in the packet.
4. Actor loss revokes its publication generation. Pipe EOF, lock release, parent-death notification and a vanished controller PID alone do not prove its command child exited or manager job finished. The survivor must establish the exact old child has terminated, resolve any accepted or ambiguous request/job, and prevent a late state write before taking the case command slot. If it cannot establish this within the case bound, mark failed/unknown and hand duty to experiment cleanup; do not exceed the helper cap or claim restored stock.
5. Restoration is a monotonic transaction phase: once restoring/closed, old activation generations can never publish an experimental claim or start. Duplicate restore requests join/reconcile that phase. Serialize publication with this phase change; checking a token before an unfenced write is insufficient. A killed lock owner cannot strand cleanup. Each boundary needs an explicit test event, including command-child survival after actor death and a late manager reply.
6. Issue the case recovery receipt only after observing exact dummy stock state and live process identity, all experimental actors gone, no outstanding writer/job able to undo it, and the required bounded evidence records. Cached receipts are historical: recheck current stock liveness on repeat requests. Experiment cleanup intervention is recorded separately and cannot satisfy a case's recovery assertion.
7. Close the case, drain/reconcile its handlers and commands, then advance the case record atomically using the reviewed owned-file protocol. Partial/invalid records refuse. Retain disjoint bounded evidence for prior cases; never clear a failure by changing the current case or starting a replacement actor.

This is a protocol requirement, not an assertion that the worker foundation implements it. Main's original worker-only source `94ddc5a79bc7f56bc02f62334c36b5c1338a9242` and reported host/build results are preparatory checkpoints; placeholder nonce/artifacts and refusing actor modes are not an executable E0T packet. The implementation and independent review must resolve the publication/command fencing mechanism concretely before freeze.

Accepted finite implementation refinement for T6-T8: only the external operator and experiment cleanup issue manager commands; case controller/guard perform owned-file operations and may spawn only the fixed compiled helper as a stock stand-in child. They do not spawn systemctl/D-Bus transport children. Their unit-start jobs must already be terminal and nonce/process/cgroup acknowledgements observed before the fault barrier; the operator must not queue a new case start during handoff. The survivor verifies the previous actor's owned cgroup empty and exact old child gone before consuming the closed-generation restore claim and spawning a stand-in. A nonblocking process-held lock plus monotonic closed record must fence every relevant file publication; document crash windows between claim, fork and identity publication explicitly. An ambiguous child birth is failed/unknown, not a reason to spawn a second child. Account for each actor plus its child in TasksMax and aggregate limits.

T6/T7 therefore measure actual owned-process/file recovery inside manager-launched units, not a new stock-unit start transaction. T5 separately measures pending manager job/cancellation behavior; passing these separately does not prove integrated service-job recovery for E1. T8 may terminate only the exact held stand-in child and verify that a duplicate request reports stale/failed liveness without respawning. This is an honest failed outcome, not restoration success. The experiment cleanup actor remains independent, and its intervention cannot supply a missing case receipt. The exact implementation must show how cgroup/child exit is observed without adding unbudgeted command children; EOF is never the exit proof.

These are one bounded comparator run, not exhaustive race testing. Each intentional termination targets only a verified owned helper, never PID-by-name or a process group containing the operator/recovery actor. If a case requires more actors or time than the frozen limits, revise the packet before execution rather than extend it live. Stop at the first unexpected result and proceed only to the reviewed cleanup path.

## Cleanup and final receipt

Latch the transaction closed; resolve/cancel only its jobs; stop exact owned units; verify their cgroups/processes empty; preserve bounded evidence on the host; remove only exact owned fragments and files whose ownership still matches; reload once; verify no owned loaded/startable units or jobs remain. Keep the cleanup actor available until these duties are discharged; its final exit/removal is performed by the independent operator and verified. No reset-failed on unrelated units, global job cancellation or reboot. An unresolved cleanup duty remains explicit and forbids E1.

Before/after and between cases check original xochitl/Reader/rm-sync PID/start identities, state, effective configuration hashes, mappings relevant to absence of new preload, and relevant job identities. Any original change terminates the experiment; record it without claiming E0T caused or repaired it. Preserve unrelated jobs rather than requiring the entire manager queue to be empty. Original physical UI responsiveness may remain unverified; no human participation is required.
