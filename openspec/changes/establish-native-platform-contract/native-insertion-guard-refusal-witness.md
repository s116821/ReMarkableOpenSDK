# Proposed native pre-insertion refusal witness

This is a separate proposed diagnostic after the
[owned principle](../../../docs/experiments/insertion-guard-owned-result.md).
It selects no artifact or tablet action. Exact machine-ABI carrier and
instruction-family evidence, source implementation, independent review and a
fresh complete native packet must precede selection.

## One question and deliberate negative case

Can two startup-installed function-entry wrappers observe one exact ordinary
creation operation, reject its deliberately mismatching source/order predicate
at the original final-map-lock boundary, and let the original handler unwind
its temporaries and mutex into the adapter's private catch, without native
page insertion or a false successful outcome?

Use a fresh operation/target ID and immutable expected document, selected
source index and immediate right neighbor. The deliberately wrong expected
source UUID must be another known page from the same disposable fixture;
its location differs from the frozen source index. Do not use invalid storage,
fake native objects, a collision target, corrupt files or an unrelated document.
The ordinary Task still names the real source index and a new target. The
guard must observe the mismatch before forwarding the map-insertion helper.
No accepted creation or automatic retry is part of this experiment.

Enforce a separate unconditional **negative-only zero-forward barrier** for
every recognized operation. Even if the deliberately wrong predicate
unexpectedly matches after a map change, do not claim insertion or forward.
That result is an unexpected-match refusal/unknown, not a demonstrated source
mismatch. A positive witness requires the actual source to equal the frozen
real source and differ from the deliberately wrong expected source.

## Exact path and ownership

The [runtime core contract](native-insertion-guard-runtime-core.md) separates
owned hook/registration/failure controls from the still unqualified native
loader, Entry and whole-packet execution.

Keep the existing selected Reader/controller/Document/Worker join and strong
native ownership. Freeze the operation record and public-Qt QString/UUID
arguments before submission. Keep that record, the native owners and all hook
code resident until controlled process termination; this experiment must not
release last native owners, reclaim a canceled slot or unload patched code.

Install both hooks before native document workers can run. The selected loader,
constructor/init ordering, untouched entry bytes and response to a partially
installed pair require explicit source and owned controls. Any failed or
uncertain installation prevents operation submission. Never patch an active
worker or claim an install-time race is harmless.
If either installation is partial, failed or uncertain, terminate the candidate
and use independent stock recovery. Do not depend on an untested unhook or
patch rollback. Submission remains disabled.

The outer wrapper first recognizes the immutable requested UUID, then validates
the exact worker and original arguments, independently of any later effective
UUID/index transformation. Its typed declaration or machine-ABI shim must be
justified by actual caller/callee register and stack evidence. Do not treat
observed machine locations as recovered original C++ type spelling.

Recognition and binding validation must be separate. Recognize the tracked
fresh requested UUID/operation first; a wrong worker, map, argument, incarnation
or spent state then refuses instead of falling through to ordinary insertion.
Define truly unrelated stock-call transparency separately. Invalid or
unreadable inputs are not made safe by guessing a signature or catching faults.

The inner wrapper requires the matching outer scope, worker/map incarnation,
thread and exact original insertion callsite. Unexpected nesting/callsite,
duplicate entry or transformed target/index must not silently borrow permission.
Only the qualified original callsite's cleanup route may carry the private
rejection exception. Any other path needs a separately reviewed transparent or
refusal policy before implementation; do not throw across uninspected frames.
For a recognized operation that reaches an unqualified inner scope/callsite,
fail the candidate process without forwarding or attempting stack unwinding;
independent recovery handles the unsuccessful run. The source and owned
subprocess controls must verify this fail-stop branch and disabled submission
after partial installation. It is never a positive rejection witness.

## Passive predicate under the original lock

The [fixed passive contract](native-insertion-guard-passive-predicate.md)
sets the cap, exact opaque receivers, checked address/span arithmetic, frozen
searches and result interpretation. Its read stage is separate from exception
runtime allocation while the original lock is held.

The original final mutex must remain held throughout predicate and forwarding
decision. Existing locking getters are excluded. The retained ordered-search
helper is only a possible route: first validate the actual under-lock vector
receiver/span and a small explicit current-count cap, then search only frozen
bounded canonical UUID strings. Expected position comparisons refer to that
same span. Frozen GUI count alone does not bound the current search.

Before implementation, independently review exact opaque receiver offsets,
alignment, record stride, normal map integrity/lifetime assumptions, returned
record semantics, comparator providers and maximum comparisons. Do not invent
private STL classes or follow a discovered page ID to new positions. Tree
membership and active-order membership are distinct. A proposed alternative
direct indexed read needs its own pinned borrowed-value contract.

The predicate performs no allocation, IO, GUI reads, refcount ownership changes
or callbacks. A single operation-bound cancellation/insertion claim prevents
late permission resurrection. This negative case must never win an insertion
claim or call the original insertion helper.
The zero-forward barrier remains effective independently of predicate success,
observer loss, cancellation and deadline outcomes.

## Outcome and independent interpretation

Catch only the adapter's private rejection after the original native handler's
cleanup. Record explicit operation-bound rejection, actual helper-forward count
zero, expected/actual predicate facts and original worker/job/Task correlation.
Unrelated exceptions are not private rejection; native propagation and partial
failure policy must be addressed before source selection. Catch-all success,
forced epilogues, skipped destructors and longjmp are excluded.
For this negative witness, unrelated original exceptions retain their original
propagation and make the diagnostic unsuccessful/unknown; an independently
recovered candidate exit is not a passing rejection. Diagnostic-owned retained
records must not acquire implicit global/static teardown that releases native
owners during an unqualified process-exit order.

The ordinary Task can finish without pageAdded. Observe both independently:
matching Task/job completion must not become insertion success. Require zero
pageAdded for this operation and no target in the reconciled active order.
Earlier native loading/status effects are not claimed rolled back.

Use the original fixed request/observation/recovery deadlines with no renewal.
On missing scope, timeout, unknown submission, unexpected notification or
ambiguous cleanup, retain owners and report the unresolved stage. Do not submit
another operation. The independently armed recovery actor must restore the
original stock process/service policy even if the GUI or wrapper fails.

Collect a fresh complete fixture baseline and exact executable/provider/
service/route/process evidence. Bind every artifact, profile, operation ID and
clock to one fresh packet. Compare all fixture bytes and page objects/order,
PDF mappings, ink/highlights, unknown metadata and full inventory afterward.
Retain every failed/unknown result; archive and remove only the owned runtime
root after independently verified stock restoration and complete readback.

Passing would qualify only this exact rejection/cleanup diagnostic. It would
not establish accepted atomic creation, GUI selected-visit exclusion, all-writer
coordination, safe native last-owner reclamation, persistence/render authority,
cross-device compatibility or shipping capability.

Source basis: current exact-build critical-section/Task/LSDA and nonlocking
helper findings, owned ARM result and existing controlled native diagnostics.
The proposed native transfer and predicate are design inferences requiring the
separate gates above.
