# Fixed identity-capture entry and original-byte image pair

October 23, 2026 UTC. Proposed continuation after the separately verified
[synchronous helper](identity-bracketed-capture.md). This selects no packet or
native execution. Reuse the existing one-request selected-view Entry with one
explicit default-off NavigateIdentityCapture diagnostic. Preserve all existing
enum behavior, schemas, modes and outputs; do not create another file-IPC manager.

## Fixed operation

The mode requires frozen canonical expected document/page IDs, index and count,
and fixed legacy fixture navigation matching the expected document/index. It is
incompatible with worker-callback, joined-creation and insertion diagnostics.
No worker acquisition, native hook installation, creation, pen input or extra
page turn is part of the operation.

Reuse the90s setup bound, one request consumption,30s operation anchored at that
consumption, one existing legacy fixture opening and its5s queued opportunity.
Do not renew a clock or retry opening/grabbing. On the admitted original
window/engine after navigation, open one exclusive owner-only pending PNG FD and
construct its bounded Sink before entering either Sample. Invoke the helper once
with at most20s and the remaining original operation budget. Keep FD ownership
and close/error reporting on the Entry stack; deleting Entry during a callout
must leave no dangling access. A pending file after failure remains forensic.

## Distinct publication admission

The existing Entry disarms before publishing, so permit() cannot be reused after
finish. Its existing generic publisher also checks setup time rather than the
new capture operation deadline. Capture therefore needs a purpose-specific
publication admission and commit path, leaving older publication paths unchanged.

Publication admission must freshly check the same root identity/owner/mode,
request inode and original bytes, candidate incarnation, absence of cancellation/
restoration, original setup AND operation deadlines, application/thread/window/
root/engine and non-suppressed result. It is a separate explicitly limited
publication permission; it neither revives a retired Sample nor calls a borrowed
guard. Entry remains one-shot and terminal even if either commit fails.

For a successful helper, close the pending PNG FD and verify named FD identity,
regular owner-only0600/single-link file, positive bounded size and byte count.
Commit the image to a fixed final name using exclusive link/unlink with checks
before/after each step. A lost check leaves pending/hardlink evidence for refusal;
do not delete/rewrite/retry it. Then serialize and publish a separate closed
capture scalar purpose under the same admission, with the original4096-byte
scalar limit. Check inode/size/times/link counts consistently across both commits.
Before closing either original writable FD, acquire and verify an O_PATH pin to
that same regular inode. Retain the image pin through both commits and the scalar
pin through its commit. This prevents an unlink/recreate from reusing the freed
inode and presenting indistinguishable coarse metadata after close; stat equality
alone does not prove continuity. Pins do not establish atomic content stability.
PNG bytes can precede the scalar; an image alone never establishes acceptance.
Refused helper results may publish bounded diagnostic scalars but cannot publish
an accepted image pair. They retain claim/unknown/partial-output facts.

The scalar binds schema/purpose, request nonce and PID/start, original setup/
operation/sample times, expected identity, actual before/fresh-after identity,
helper attempted/captured/unknown/refusal, width/height/storage/DPR/encoded size
and SHA-256, and false native/render/durable/atomic authority. State full-window
coordinates, sampled logical identity, Qt window acquisition and unverified
backend/page-content/physical freshness explicitly. Keep useful/blank content
as subsequent image inspection, not an automatic scalar assertion.

## Startup and consumer

An explicitly selected startup variant must reject fixture macros and incompatible
modes. Before any future exec helper, clear LD_PRELOAD/LD_BIND_NOW from the current
process environment using the already exercised child-environment primitive;
retain the parent DSO mappings. This variant needs separately reviewed exact
target/provider/packet/actor/incarnation/deadline admission. It must not call the
insertion profile installer simply to obtain that admission: no Dobby or native
insertion hook is required for this public-Qt capture diagnostic. Earlier startup
variants retain their original behavior.

The host consumer requires exact original closed scalar bytes, finite correctly
typed values, unique keys, bounded UTF-8, expected purpose/request/incarnation,
strict timing/identity/authority implications, and original matching image bytes.
Both files must be regular, owner-only, single-link, stable under fresh request/
process/restore brackets and within existing size/storage/pixel quotas. Reject
pending duplicates, partial commits, stale/changed/wrong-purpose pairs or unsafe
names. Verify SHA, dimensions and complete decode locally before acceptance.
Formatted JSON is only a parsed copy. Orphans remain forensic and are archived.

The archived-byte validator is a separate part of that consumer: it cannot
establish live file modes, link counts, request identity or process/restoration
brackets from copied bytes. Its positive result must leave external admission
unverified. Its fixed PNG profile accepts static truecolor RGB/RGBA at 8/16 bits,
requires complete CRC/deflate/scanline and local pixel decode, and refuses indexed
or grayscale data and compressed ancillary metadata (`zTXt`, `iTXt`, `iCCP`).
Unsupported originals remain unchanged and forensic. This deliberately limited
diagnostic decoder does not promise a general PNG reader or total decoder memory
bound equal to the captured image's reported storage size.

## Verification and later selection

Owned Entry controls must exercise real one-request files, fixed navigation seam,
helper delivery and separate publication, including cancellation/reentry/lifetime
loss, operation/setup expiry before and after each image/scalar link, stale or
replaced files, overquota/partial output, late helper return and unchanged old
modes. Consumer controls include original valid/refused pairs and malformed,
duplicate-key, Unicode, numeric, schema/purpose, timing, image hash/decode and
pending/link cases. Use actual owned serializer output when available.

Only afterward prepare/review a fresh committed source/artifact/provider/consumer/
recovery packet against the current eleven-page/24-file fixture, with a complete
fresh backup and explicit preservation rules before activation. Preserve all
existing page objects, ink, PDFs and unknown metadata. Independent recovery and
full stock/process/policy verification remain required. No old spent packet,
second creation or changed event guard substitutes for this work.

Source basis: current selected-view Entry, helper/capture core and exercised
child-environment primitive; independently reviewed source observations. The
mode, file publication and archived-byte validator now have a separate
[owned implementation checkpoint](../../../docs/experiments/identity-capture-entry-owned-result.md).
Live file/request/process/restoration consumption and a fresh native packet/load
remain unimplemented or unqualified; this design does not grant native authority.
