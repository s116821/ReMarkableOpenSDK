## Distinct refusal-only record

The selected DEV entry writes `refusal.json`, mode0600, no-follow/exclusive creation,
at most 2048 bytes, only for reader-completion/read-delivery or entry-completion
refusal. It writes after the nested reader/getter stack and before the refusal
callback. The success callback remains exactly four fields and successful private
facts remain exactly 23 fields. Successful reads produce no refusal record.
The new shape is exactly 27 fields, kind `development-facts-refusal`, version1.
It contains no document/page values, pointers, raw QML errors or proprietary bodies.
It is not accepted by the fixed successful facts validator and cannot grant
atomic, native or render authority; those three flags are always false.

| Fields | Meaning and limit |
| --- | --- |
| nonce, attempt_pid, attempt_start | Entry's already validated private attempt identity |
| reader_stage | One of 17 existing reader/owner labels; any other string becomes unlisted-reader-stage |
| reader_result_had_facts | Typed record of the reader result at the entry callback; never usable facts authority |
| entry_stage | Unchanged facts-entry-read-refused or facts-entry-delivery-refused |
| refusal_path | reader-result, entry-read-boundary or entry-completion-boundary |
| sample_phase | before-refusal-callback; recording-time checks, not first-failure history |
| sample_ms | Original entry setup-clock sample at recording |
| request_accepted_ms | Original accepted-request timestamp; never reset |
| accepted_read_elapsed_ms | Sample minus accepted timestamp, including dispatch/read/queue/record delay; -1 only if not accepted |
| setup_clock_origin, read_clock_origin | entry-startup-monotonic, accepted-request-monotonic |
| setup_budget_ms, read_budget_ms, setup_selection, development_setup_opt_in | Fixed selected120000/5000/main-dev-facts-120s/true; writer requires this opted-in config and read budget |
| entry_context_current, root_identity_current, closure_absent, attempt_identity_current, within_accepted_deadline | Typed passive entry checks at recording; deadline uses acceptedRequestAt+5000 |
| atomic_snapshot, native_authority, render_authority | Always false |

The checks are sequential and non-atomic. A recording-time false flag may describe
a later boundary loss, not the reader's first failure. The reader stage preserves
an existing failure family, not an individual missing metadata signature/getter.
An allowlisted `facts-observed-no-change-during-read` paired with an entry refusal
describes a rejected reader result; it is never promoted into live success.
`open-*` stage names are existing shared owner-discovery labels; no OPEN call is added.

The entry stores only the filtered reader label and had-facts bit; the original
read/admission/delivery short-circuit checks remain in place. Recording invokes
no new document/page getter or observer, makes no retry, and resets no clock.
Missing, stale, partial or failed refusal I/O remains unknown. The entry never
overwrites an existing refusal file; a preexisting record also refuses new startup.
Root loss can prevent both diagnostic and callback publication. No hard syscall
preemption or guaranteed diagnostic delivery is implied.
