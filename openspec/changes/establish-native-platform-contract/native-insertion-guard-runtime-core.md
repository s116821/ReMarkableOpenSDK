# Negative-only hook core and installation controls

This refines the [native refusal witness](native-insertion-guard-refusal-witness.md)
before implementation. It is not a loader, native Entry, execution packet or
shipping component. The [passive predicate](native-insertion-guard-passive-predicate.md)
remains a separate read-only dependency.

## Installation and process lifetime

Use only the separately recorded owned Dobby variant with explicit ARM-mode
initialization and logging compatibility overlays. Preserve older libraries
and results. The underlying relocation warnings, unchecked patch/protection
returns and absence of a drain/unload protocol remain unresolved.

An injected install interface permits owned functions to exercise the actual
two-entry mechanism without resolving native addresses. A future native
loader must independently qualify the executable/profile/providers and
installation before native document workers can execute. A Boolean caller
assertion is not evidence of that runtime fact.

Before mutation, check both original eight-byte entry sequences and reject
overlapping overwrite ranges. After each hook, independently verify the actual
ARM absolute-entry branch/replacement word and the relocated trampoline's
original eight bytes plus branch back to the original entry+8. Recheck both
complete entries and trampolines after the second installation, before publishing
the verified pair. Validate the relevant executable mappings/protections.
Do not credit DobbyHook returning zero as these facts.

Only a completely verified pair can permit registration/submission. Null,
misaligned or mismatching originals, unexpected bytes/permissions, partial
installation, a failed second hook or an early intercepted call before complete
initialization fails the candidate. Terminate it and recover independently;
do not use DobbyDestroy, rollback an untested patch or continue with one hook.
Owned subprocess controls must demonstrate these paths without tablet access.

Keep code, originals, registry and the tracked record resident until process
exit. Native owners belong to an intentionally retained heap record, not a
destructible global or temporary wrapper. The eventual native loader's exact
linked init_array ordering must be reviewed, including selected library static
initialization before installation and installation before application workers.
This core alone does not establish that ordering.

## Carriers and registration

Use justified machine carriers preserving opaque pointer/reference bit values,
full integer flag words and the two hard-float size values. No native private
class is declared or synthesized. Public Qt UUID/QString arguments may be
interpreted only under their separately qualified exact public ABI/lifetime.
Match the observed eight outer argument locations and six inner locations;
do not narrow the inner sixth word to bool.

Registration happens once, after native owner/binding/thread facts and immutable
UUIDs have been frozen outside the critical section. It requires a fully
verified hook pair. No replaced record, renewed deadline or second operation.
All cross-thread terminal/cancellation/observation fields need explicit
synchronization. The core cannot establish native ownership from a pointer or
admission flag; those are caller obligations of the future Entry.

Recognize the requested UUID before checking worker/index/source/incarnation.
A recognized mismatch refuses before entering the original outer handler;
it must not fall through transparently. It is not a positive inner-predicate
witness. Truly unrelated calls forward transparently through exact carriers.
Nested unrelated outer calls suspend the tracked scope so their inner calls
cannot borrow its permission. Any observed interference prevents an unsupported
positive interpretation; do not hide it as a clean tracked observation.

## Tracked execution and private rejection

The tracked original outer handler runs inside a private-exception-only catch
with an owned stack scope. Require the qualified original outer caller, worker
thread and original arguments. A duplicate recognized outer call cannot invoke
the original again.
Initialize worker-local scope/TLS and any required lazy runtime binding before
entering the original handler. A source-level no-allocation predicate and an
owned C++ new counter do not prove all lazy runtime setup is allocation-free.

At the inner wrapper, require that scope, exact original insertion return PC,
worker/map relation, calling thread and single entry. Preserve eligibility
when effective UUID/index changes; record a refusal. An unqualified tracked
inner path fails the candidate without forwarding or throwing across unknown
frames. Never probe the native mutex to infer ownership.

Only the qualified inner path may run the passive predicate and throw the
private marker. Regardless of predicate result, cancellation, deadline or
observer state, the tracked original insertion helper is never called.
Unexpected-match, canceled, transformed-input and other refusals remain
distinct from the intended source-mismatch witness.

The outer catch records that private rejection after original native cleanup.
It never manufactures a pageAdded event, successful insertion or owner release.
Unrelated original exceptions preserve propagation and make the diagnostic
unsuccessful/unknown; candidate recovery is separate. Exception transport may
allocate while the original mutex is held; only the passive read stage is
allocation-free.

## Owned source verification

Use original owned bodies and exact target instruction-family prefixes, actual
QThread execution and the pinned repaired library. Verify carrier forwarding,
actual patched/trampoline bytes, source-mismatch rejection and original cleanup,
tracked/foreign/nested/duplicate paths, transformed arguments, cancellation,
registration/installation failure and fail-stop subprocess outcomes.

## Separate pre-handler attribution callback

The future Entry must correlate this ordinary Task with the original native
worker job. Permit one explicitly injected, noexcept attribution callback only
after tracked outer recognition/binding/thread checks and before calling the
original outer handler. It may return one nonzero opaque job ID; a failed or
zero result refuses before the handler and is not an inner-mismatch witness.
Never invoke it for unrelated, duplicate or invalidly bound work. Publish the
result only through synchronized completed snapshots.

The callback's native implementation is outside this core. A candidate route
is a separately qualified nonblocking acquisition of the worker queue mutex,
reading the existing active-job words and immediately unlocking, entirely
before the final map lock. Busy/error means refusal, with no wait or retry.
This is not mutex probing to infer original final-map ownership. Exact offsets,
call provenance, pthread ABI/providers and all return paths still need their
own source/profile review. The passive predicate never acquires this mutex.
An injected callback and owned tests do not establish that native contract.

Retain original failures and exact input/library/output hashes. Owned tests
cannot qualify the actual native loader, original native cleanup, borrowed map
storage, job/Task correlation, restored device state or supported capability.

Source basis: current reviewed refusal/predicate proposals, exact native
machine-location/LSDA findings, owned ABI evidence and pinned upstream
installation/lifetime review. This is proposed original control logic.
