# Version-free source and Cargo-generated metadata

October 12, 2026. REM-50 remains the release/staging owner. This SDK increment
addresses its reported refusal of the prototype `0.0.0` source fields without
adding a version calculator, bump commit, runtime identity framework or release.

## Evidence and proposed contract

The prototype manifest's explicit `version = "0.0.0"` was introduced once at
SDK523d396 and never bumped. No SDK Rust API exposes CARGO_PKG_VERSION or a project
release version, and there is no build.rs. Nevertheless the maintainer's October 3
rule prohibits maintained project-version fields even when called placeholders.
Remove the explicit version from the root and standalone consumer manifests.

[Cargo's manifest specification](https://doc.rust-lang.org/cargo/reference/manifest.html#the-version-field)
says omission defaults to 0.0.0 since Cargo 1.75; supported Rust/Cargo 1.88 can use
this normally. Cargo generates that value in metadata and its mandatory lockfile
own-package entry. Retain those generated entries and all dependency pins. They
are development/package-resolution metadata, not a canonical SDK release version.
Deleting their version fields or hand-rewriting locks would break the locked
consumer contract and is not this change.

REM-50's inspected `stage_source.py` at
[`6008083`](https://github.com/s116821/ReMarkableOpenSDK/blob/600808384a7e111d1a0a905cfcdcd1eac6f87934/release/stage_source.py)
currently refuses any own-package lock version, including Cargo's generated
default. It also records the own entry among dependency_lock while later
comparisons exclude it. The release owner must reconcile both checks:

- Require absent own manifest/workspace version in exact source.
- Accept only a single generated own lock entry at Cargo's 0.0.0 default, without
  a dependency source/checksum; a missing own entry can be generated by Cargo.
- Keep upstream dependency records unchanged and separate from the own entry.
- Derive the official staging manifest/version solely from the already existing,
  verified tag and exact intended source SHA; let Cargo regenerate its own staging
  entry accordingly. Do not commit a generated version or change source locks.
- Immutable Git consumers retain tag/revision and exact locked commit identity;
  Cargo's default package version must not be presented as release identity.

This is a proposed ownership handoff pending SCRAPPY confirmation, not a claim
that its existing verifier already supports the generated-lock exception. Official
tag-before-build, maintained upstream tooling, docs-only exclusion, source identity,
native qualification and publication gates remain unchanged.
