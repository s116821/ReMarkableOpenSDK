# Conditional insertion followed by one adjacent acquisition

This is a default-off research continuation of the conditional coordinator, not
a supported navigation API. The fixed conditional trial preserved the source
selection after creation. The earlier [joined creation result](../../../docs/experiments/joined-creation-selection-result.md)
already establishes one stock `moveForward()` route. Integrate that continuation
with the conditional Core/job/post-order correlation in one retained runtime.

## Admission and one-shot helper

Add `Config::wantTargetAcquisition=false`, valid only with conditional forwarding.
Before acquiring native owners, retain QPointer identities of the actual joined
Reader and document and inspect Reader method metadata under the borrowed fresh
Sample guard. All later joins in this mode must match these identities, as well
as the original window/engine and deadline. A destroyed or replaced object refuses.

Use an original GUI-only `reader_insertion_target_acquisition` helper with owned
MethodInfo, Claim and Result values. Inspect at most 512 methods, requiring exactly
one public Method/Slot `moveForward()` with zero parameters and return type void
or QVariant. Record its index, bounded signature, declaring class, return type,
access and kind before creation. Signature/declaring class/return name are capped
at 64/64/32 UTF-8 bytes. Missing, ambiguous or unsupported metadata
refuses before native owner acquisition, probe, registration or creation. Do not
infer exact runtime metadata from the earlier union-contract invocation.

Dispatch accepts the frozen creation request, its freshly observed complete N+1
post-order, admitted metadata, same engine/Reader/document identities, a shared
single-use Claim and the borrowed Sample guard. Copy inputs before callouts;
guard GUI/thread/lifetime/reentry/exception and QML engine association. Validate
all original IDs plus the unique target immediately after source. Current Reader
may be source or target only. If target is already selected, record that fact
without dispatch. Otherwise source has a known right neighbor, so the stock
end-of-document creation branch is excluded by the observed post-order.

Reinspect and compare exact metadata before dispatch and check the guard once
more immediately before consuming the Claim. Consume before one DirectConnection
invoke, including invocation failure or exception. Never retry creation or Next.
Never test the old source-epoch guard or dereference borrowed objects after the
intentional page change. The returned Result contains only owned facts: admitted
metadata, attempted, dispatched, unknown, alreadySelected and refusal. A shared
Claim survives facade deletion and prevents a reentrant second invocation.

This is sampled idle-fixture admission, not atomic exclusion of all concurrent
writers or input. Stock moveForward exits text mode and rereads currentPage;
reentrant state changes across that callout are a separate product qualification.
The helper neither emits native authority nor proves target selection.

## Coordinator transition and reconciliation

Preserve schema1 negative mode and schema2 conditional-only behavior. New mode
adds pre-creation metadata admission and pinned Reader/document checks to First,
Second and Post. Post still requires the normal committed Core return, exact job,
callback, matching completion/pageAdded index and full N+1 public GUI order.
The one Next dispatch is the terminal action of that fresh joined Sample.

After dispatch, enter a distinct AfterNext observation phase with a two-second
queued settling opportunity, capped by the original absolute thirty-second plan.
The old Sample epoch ends at intentional dispatch. A new Sample must rejoin the
same Reader/document/window/engine and observe complete expected N+1 order,
target ID at source+1 and ready/error-free state. This explicit correlated
transition must not clear or revive a failed old epoch. Already-selected Post
can complete without dispatch after the same final Core checks.

Read-only readiness observations may settle within the existing bounded attempt
cap and original deadline. A missing/replaced identity, lookup/metadata/epoch
failure or unexpected order refuses. Never retry the effect. Recheck Core and
indexed events at completion; post-commit failures retain forward facts and
require reconciliation. An invocation return alone is not target acquisition.

## Wire, startup and verification

Select the new mode only with frozen `READER_INSERTION_SELECT_TARGET=1` plus
`READER_INSERTION_FORWARD=1`. Incompatible selectors refuse before main. Use a
distinct closed schema3/diagnostic/stage with the existing schema2 insertion and
post-order facts plus target_acquisition metadata/dispatch facts and final fresh
selection scalars. Final order is checked in full internally; do not duplicate
its ID array on wire. Preserve the 4096-byte cap and original clocks. A separate
strict consumer binds the candidate and requires the complete creation plus
target-selection conjunction, never just method acceptance. Keep authority flags
false and incomplete/unknown outcomes explicit.

Owned host/ARM/sanitizer controls cover exact metadata admission and drift,
ambiguous/wrong return/access/arity/signal, reentry/deletion/guard loss, consumed
failed/throwing invocation, intentional old-guard loss after dispatch, already
selected/no Next, source-at-end before insertion, full order drift and unrelated
Reader/document replacement. Coordinator controls cover pre-effect admission,
same retained identities, one Next, separate fresh ready target, late Core failure,
post-dispatch timeout/cancel/unknown and unchanged old mode outputs. Verify wire
positive/incomplete/boundary cases including N=16 without extending the cap.

Any native trial needs fresh committed source/artifact/provider/consumer/recovery
review and a new nonce. The current fixture is ten pages/twenty-two files; the
spent nine-page admission is invalid for another attempt. Preserve all current
pages and original ink/PDF/unknown metadata, with full before/after readback.
Selected blank pixels, writing, reopen/persistence, end/notebook coverage and
supported consumer/lifecycle qualification remain separate gates.

The [owned implementation and verification checkpoint](../../../docs/experiments/conditional-target-acquisition-owned-result.md)
records source controls and separate ARM link builds. No composed native run is
established by that checkpoint.

Source basis: current conditional result, retained shipped QML/REA findings and
the earlier actual adjacent-selection result. This document is a proposed
composition; it does not claim an integrated native selection result.
