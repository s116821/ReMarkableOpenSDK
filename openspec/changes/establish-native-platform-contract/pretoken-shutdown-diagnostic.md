# Pre-token FactsEntry shutdown discriminator

October 8 source preparation only. Main selected this follow-up after a
first-render-admitted lifecycle-only run ended by SIGTERM without reproducing the
original rendering SIGSEGV. Neither systemd success nor absent Qt quit markers
proves graceful Qt shutdown. The original fault and native production gates remain
open. No new nonce, device operation, native artifact or guard change is selected.

## Controlled question

Add the original FactsEntry pre-token lifecycle to the scalar recorder: parentless
construction, start validation, application event filter, directory watcher,
precise setup timer, queued bounded window/QML-engine bootstrap, cancellation,
queued completion and deleteLater. Preserve the source-facts configuration shape,
but exclude request admission at compile time. This tests that cohort and its
timing, not an individual filter or destructor. No contact, page-owner discovery,
active page getters, source reader, image capture or forced Qt quit is permitted.

The original source reader requires a published token. Preserved original host
evidence does not establish completed readiness/contact/publication. Therefore
configuration enabling source facts is not evidence that the reader ran. A
matching fault in this diagnostic would establish that active page getters are
unnecessary for that occurrence; a non-reproduction leaves the cause unresolved.

## Compile scope and admission fence

Only a separately compiled target defines `QT_FACTS_PRETOKEN_DIAGNOSTIC=1` for
every translation unit, including generated FactsEntry MOC. The normal target is
unchanged without the macro. In diagnostic builds the queued request callback
returns before input/capture/facts admission, including before
`acceptCaptureRequest`; an additional entry guard in that function refuses direct
admission. Unexpected tokens cannot reach owner discovery, getters or reader
construction. No public runtime switch or accepted capability is added.

The lifecycle recorder startup calls a diagnostic-only entry helper after opening
the recorder and connecting its normal signals. That helper preserves the
original startup config validation and completion callback scheduling deleteLater,
except the explicitly selected diagnostic root. Fixed synthetic canonical IDs
satisfy the original six-page config shape without reading document identity.
It does not manually cancel, delete, invoke quit, or alter service policy.

## Proof interface for Main and consumer review

Retain the v1 ten-field trace, 192-byte record and 96-record/18432-byte limits.
Add one event name, `entry-installed`, emitted synchronously on the GUI thread
only after FactsEntry start has installed its watcher/filter/timer and queued
bootstrap without refusal. It is not engine readiness, page readiness, lifetime
completion, a render fence or a promise the object remains live. Start refusal
emits no installation event and must never admit a diagnostic STOP as successful.

Recorder and diagnostic FactsEntry share `/run/rmb-qt-shutdown-<nonce>`. Main's
future reviewed actor owns this root with matching nonce and current PID/start
binding, root UID0/mode0700 and private owner/identity files. No request publisher
is staged. The diagnostic does not transplant the original probe root or unsafe
historical restoration script. No native staging is authorized by this file.

Main explicitly selected this shared-root tradeoff to preserve reviewed actor
ownership/recovery. Actor evidence-file creation may stimulate additional
original directory-watcher/request callbacks. The compile fence prevents
admission, but this coarse cohort/timing comparison cannot isolate a particular
filter or watcher. The earlier two-root proposal is not active.

Main's explicitly selected cohort STOP proof requires exactly one matching
`entry-installed` event and a valid
first `before-render` in the same ordered trace/process identity, zero drops and
the existing strict scalar checks, with quit_seen zero. Installation must precede
the qualifying before-render and share the startup GUI TID. The selected parser
requires installation frames zero, but the SDK cannot universally guarantee it:
original direct render connections precede the synchronous helper, and a render
thread could run concurrently without a nested GUI event loop. Preserve actual
counters; nonzero installation frames refuse admission. Do not reorder binding,
pump events or reset counters to manufacture zero. The parser need not constrain
window versus entry ordering. Unknown events are refused. No engine-ready or
Qt-quit wait is added.
Missing installation, refusal, timeout or malformed evidence remains inconclusive
and converges to the existing independent recovery duty. Keep the current guard,
absolute budget, stock policy and one-stop behavior. Installation plus first
render describes exposure, not proof of a later teardown path.

## Targeted verification and review gates

- Unexpected valid and malformed facts/source/capture tokens after installation
  cannot set admission/discovery state, construct a reader, invoke fixture page
  getters or create page/capture outputs; no repeated request changes that.
- Start refusal produces no `entry-installed`; deferred completion and deletion
  remain valid without early destruction or duplicate callback.
- Destruction of an owned QML engine triggers the original cancel/finish/queued
  completion/deleteLater lifecycle; no fixture directly calls cancel or forces
  application quit to manufacture native evidence.
- A normal build without the diagnostic macro still admits the existing owned
  facts fixture. Baseline recorder signal/cap/failure behavior stays covered.
- Exact ARM compile and owned QEMU fixtures are source evidence only. Compile-only
  synthetic configuration is not a selected native payload. Main/Root review the
  source freeze, consumer proof and shared-root ownership before any fresh artifact.

Native signals may bypass Qt aboutToQuit/destructors. Late-render events still
depend on aboutToQuit and cannot exclude rendering after actor STOP. Additional
events after an admission snapshot do not establish their order relative to signal
delivery. No raw documents, core memory or proprietary disassembly are published.

## Source verification checkpoint

Run `sh /src/tools/qt_pretoken_shutdown_test.sh` in the pinned RM2 SDK image
`sha256:416c7a7be0038156797b0892f031f352b841d1921fae83f712d0a272e4724618`,
with repository mounted read-only at `/src`, private writable `/out`, network
disabled and ephemeral `/run`/`/tmp`. The script records exact compiler arguments
and traces all MOC/compiler commands. The diagnostic macro is passed to all
diagnostic translation units and MOC; the separate ordinary control omits it.

Nine owned ARM/QEMU cases pass: valid source and capture tokens, malformed token,
normal/input fallback flags, truthful nonzero installation frames, and identity,
config and stale-start refusal. Engine destruction exercises original queued
cancellation/completion/deferred deletion without direct cancel or Qt quit calls.
The macro-absent ordinary facts-admission control passes. The existing recorder
fixture also passes its cap, signal and failure checks. Its synthetic Qt signal
invocations are owned fixture plumbing, not native shutdown evidence.

The ordinary entry header and startup source, after excluding diagnostic-only
preprocessor sections, match the frozen predecessor exactly. Installation records
require the actual successful boolean result of bootstrap invokeMethod, not merely
the original bootstrapQueued flag. The fixtures cover successful posting and
synchronous refusals; no artificial failure hook claims to model a failed Qt
enqueue with a live context. The SDK nonzero-frame fixture verifies truthful
output; strict parser rejection remains the consumer's separately reviewed test.

Initial fixture failures were test expectations: broad event draining also
processed deferred deletion, and config refusal before root opening correctly
has no callback file. Final tests inspect queued completion separately from
deferred deletion and do not require output from an unopened root. Private logs
preserve those failed runs. No native source-facts operation, fresh nonce or
hardware qualification follows from these checks.
