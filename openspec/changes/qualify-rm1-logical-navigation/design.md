# RM1 mapping and completion boundaries

## Shipped shared boundary

The implementation reference is SDK v0.2.0, commit
`a0c6480be6785480c2e0da76a3c06697a18efae4`. This supersedes the old
fb68f56/f6b7dc8/b58a59b research snapshots as the integration reference, without
promoting historical evidence into RM1 qualification. The tagged source retains
this active change and all nine unfinished native tasks.

Reuse persistent identities, LogicalDirection/NavigationRequest, resident
protocol revision 4, authenticated retained-directory transport, one-use
activation admission, absolute deadlines, durable mutation reservation,
uncertainty without replay, and historical ReaderFacts/capture boundaries.
The owning [resident specification][resident-spec] defines these contracts;
this change does not duplicate or widen them. Enabling native-adapter does not
upgrade UnqualifiedPlatform. Historical facts/images do not construct live
PageObservation guards, establish settled physical freshness or authorize writes.

Returned RM2 research was inspected before identifying remaining work:
05af65656e07c939349c9a10419ba94cd8b7457e supplied measured Reader identity/capture
and insertion/retirement mechanisms imported into the delivered adapter. Their
provenance/adaptation is recorded in [resident components][components] and the
completed integration's source/result records. Reuse these mechanisms and
refusal/fixture patterns; no new generic runtime, discovery framework or mock
native-facts producer is needed. These are RM2 records, not RM1 qualification.

The [gesture planner][gesture] explicitly returns UnimplementedPair for
Remarkable1, including portrait. The [installed Reader profile][rm2-profile]
supplies no enabled generic native-selection path: its installed build leaves
Select, ordinary-close and fixture-reopen routes disabled. Logical adjacent
navigation needs an explicit RM1 mapping and its own evidence; SelectAdjacent
framing alone is not dispatch authority.

## RM1 profile and evidence

Historical metadata: RM1 cyttsp5_mt/event2, X0..767, Y0..1023, slots0..31;
probe source28cfca140b4325999ecea2abce31b612d79fef8a. The reviewed probe clears
incidental current values returned by EVIOCGABS and never reads the event stream.
These ranges and framebuffer allocation do not establish orientation or source
identity. See the [matrix](profile-evidence-matrix.md) for separate evidence gaps.

The retained baseline has firmware3.28.0.172 and Qt6.10.3, but its xochitl and
Qt Core hashes differ from the delivered RM2 profile. The exact-build loader
also checks provider/code/ABI facts. Replacing a model name, digest or address
table is not an RM1 port. Actual RM1 joins, native owner/control layout, input
conversion and physical retirement remain unqualified. ARMv7/version equality
cannot satisfy these gates.

## Qualification and authority

Qualification needs an own backed-up disposable notebook/PDF fixture, reviewed
RM1 model/runtime/input profile and separate logical-to-physical orientation
mapping. Revalidate actual source, intended adjacent target and complete order
before dispatch; refuse stale ownership, profile or orientation. Issue at most
one supported gesture, never a blind retry. Already-target requires no input.
Completion needs the intended native target, unchanged expected order and
attributed fresh settled pixels before any consumer binding/write.

Historical capture is evidence for its named procedure, not an implementation
of that stronger freshness requirement. If an RM1 producer cannot establish the
required correspondence/settling, remain unsupported or uncertain without
consumer binding/write. Do not fabricate revisions/input epochs or turn two
matching samples into atomicity. Unchanged, uncertain and unsupported outcomes
never grant authority.

Advance notice, exact source/artifact/operator review, full own-fixture backup,
bounded independently functioning recovery and owned cleanup precede any later
idle-tablet trial. Compilation or source review is not hardware permission.
No runtime hook, input, restart, device operation or native experiment is selected.

## Smallest later read-only refresh

After existing device/operator holds are cleared and the sole operator verifies
the intended key-only USB alias, reuse the existing collector with only two
explicit per-invocation transport corrections: `UpdateHostKeys=no` prevents
authenticated host-key maintenance, and `ConnectionAttempts=1` pins the single
connection bound independently of inherited configuration. Keep
`StrictHostKeyChecking=yes`, key-only authentication, forwarding controls,
connect/outer deadlines, fixed remote reads and all parser/output bounds.
No config/known_hosts edits, wrapper, alternate route or replacement transport
are introduced. An owned transport control must inspect the actual spawned SSH
argv, requiring each safety option once before the alias and the unchanged
remote command; no contrary duplicate may permit maintenance or retries.

The source baseline before this correction was delivered collector SHA256
`281fb718e99904956aa13003f30dd4b7dfcf5d6517f8cb0d819413af6229a2dc`,
at local `tools/collect_rm1_baseline.py` / delivered
`scripts/collect_rm1_baseline.py`. Review the exact successor hash before use.
It needs host Python/OpenSSH only: no upload, installation or native load.
Retain its16KiB output/30-second outer bounds, fixed remote reads, strict host-key
checking and generic diagnostics. Use a fresh private host output path because a
successful observation atomically replaces the selected output file.

It refreshes model/architecture, firmware, before/after xochitl/Qt Core/PID
checks, root/home capacity and framebuffer allocation. It does not collect input
ranges, libc/provider inventory, orientation, service recovery, page identities or
pixels. Do not silently expand the command to claim those facts. A mismatch
invalidates the old profile candidate; a match still grants no native authority.
No SSH or collector execution is part of this source delta.

## Observation-only admission before navigation

### Evidence and decision

The November5 private RM1 comparison, recorded in
[REM-49](https://linear.app/magentumdragon/issue/REM-49), located the four Reader
anchors in compressed embedded QML and checked the static document/page-map,
SceneView/controller/tile and library lookup declarations. These observations
support source reuse; they are not live object relationships, registered
QMetaType flags, provider resolution or successful capture. The retained original
files remain private inputs, never source/release assets or family fixtures.

The current `ReadOnlyBackend::submit` uses only `core`, `applicationAbsent` and
`baseAdmission.profileAndProviders` as its Facilities gate. Its observation and
capture paths do not call the insertion-hook core. Nevertheless, the current
bootstrap's `installBeforeMain(false)` installs that core, and the observation
build links Dobby and mutation/creation-bridge code. Disabling the conditional
mutation executor does not remove those startup effects.

Introduce a separate, explicit RM1 observation admission and bootstrap. Share the
existing historical dispatch mechanics, not insertion Facilities, private owner
layouts or RM2 qualification. Do not construct a dummy core, accept a boolean
from a caller as admission, relax the RM2 gate, or discover every RM1 insertion
hook to satisfy this incidental coupling. This is a limited preparation slice of
this active change, not another runtime or native-facts API.

### Admission and lifetime

The RM1 bootstrap must independently bind its exact reviewed profile, actual
executable and adapter mapping/file before exposing an endpoint. Reuse the
existing one-use `Activation::claim`, boot/parent incarnation and nonce checks,
consumption marker and retained-directory correspondence. Retain the existing
effective-UID, file stability/ownership/mode, ELF/mapping, ARM32 little-endian
hard-float and required Qt/C++ ABI checks. Require actual pre-main ordering,
application absence, eager binding and process-resident/NODELETE lifetime; keep
the startup checks on the actually linked artifact, not a fixture's assertions.

An RM1-specific, privately constructed admission record is issued only by the
RM1 verifier after all its checks succeed. It is not an operational page guard or
a product capability. Its request-time validity includes the original process
and retained activation directory. The shared dispatch implementation cannot be
constructed/called through a public unadmitted entry point. Keep the RM2 facade's
existing Facilities gate at the same admission boundary; it does not accept an
RM1 record as a replacement Facilities object.

Identify the actual providers of every ABI-sensitive dependency used by the
linked observation artifact, including Qt Core/QML/Quick/GUI/Network and required
C/C++ runtime dependencies. Verify exact reviewed provider file identities,
loaded mappings, required symbol/version definitions and actual eager bindings
where applicable. Preserve executable/file-backed mapping and artifact
correspondence. The three retained xochitl/Qt Core/libc inputs do not establish
this closure, and an RM2 sysroot or equal Qt version does not establish RM1 ABI.
No missing pin, unresolved provider, unknown startup condition or absent runtime
evidence defaults to success. There is no currently approved RM1 profile/binary
pair; this design does not mint one or populate gaps from static marker matches.

Keep activation-directory removal and inherited `LD_PRELOAD`/`LD_BIND_NOW`
clearing, queued GUI startup, kernel-authenticated endpoint peer, retained socket
directory and original absolute deadlines. Invalid bootstrap admission exposes
no endpoint and follows the existing fail-closed bootstrap termination contract;
do not clear consumption evidence or retry. Request retirement ends publication
authority without unloading the module or routinely restarting xochitl.

### Historical dispatch boundary

Reuse Observe, presence-only reconciliation, CaptureSource and visual-only
capture under their existing revision4 meanings and bounds. Reject Insert,
Select, close/reopen and unknown commands before native dispatch. Presence
reconciliation must not clear a mutation reservation or uncertainty quarantine.
Do not advertise logical navigation, operational PageObservation, fresh settled
pixels or write authority from a historical result or from admission alone.

Keep the original GUI-thread/focus/window/engine and QObject lifetime checks,
bounded census and notification epoch, exact selected-source/order guards,
two-pass order and two guarded source samples, private PNG until final admission,
reentry/cancellation/deadline refusal, output bounds and post-encoding checks.
Visual-only capture still requires its original context but invents no Reader
identity. No new wire revision, fabricated revision/input epoch, mock native-facts
producer or alternative diagnostic fallback is needed.

The existing source-action branch is used with an empty worker-action callback;
it does not acquire a DocumentWorker owner or submit a worker task. Resolving
the DocumentController singleton may initialize it; entry lookup may allocate or
cache a wrapper; capture invokes rendering. Therefore observation-only is not a
promise of zero in-process effects or harmless loading. A separately selected
trial still needs exact artifact/operator, disposable own-fixture and independent
recovery review. Public RM1 capabilities remain unsupported until the relevant
native acceptance is qualified. No trial is selected by this source design.

### Meaningful validation plan

1. **Unforgeable admission and actual correspondence.** Compile rejection controls
   for direct construction/copying of the sealed record. In owned process/ELF
   fixtures, change one real input at a time: executable/provider bytes, file
   stability or backing mapping, required symbol/version/provider binding,
   eager-binding state, ABI evidence, application/startup ordering, process or
   retained directory. Each mismatch refuses before socket/capture work. A
   fixture success is only a verifier-mechanics result; it cannot supply missing
   target provider pins or admit RM1. Do not add a success-by-test-boolean path.
2. **Activation and endpoint regression.** Reuse the existing real filesystem,
   process and local-socket controls for consumed/expired/mismatched admission,
   replaced directory, wrong peer, cancellation, late reply and absolute deadline.
   Assert no endpoint before admission, no automatic retry/marker removal and no
   publication after retirement. Preserve the same behavior through both facades.
3. **Dispatch equivalence and forbidden effects.** Reuse existing owned Qt/order/
   capture fixtures to compare accepted historical replies and refusals before
   and after extraction. Cover wrong context/source/order, notification/reentry,
   cancellation and loss after PNG encoding. Check that all mutation/selection/
   close/reopen/unknown commands refuse without native effect or quarantine
   clearing. Model data tests these guards only, never target compatibility.
4. **Build dependency and RM2 regression.** Inspect actual compiler/linker inputs
   and emitted ELF dependency/symbol records for a future RM1 build: no Dobby
   hooks, insertion/owner/mutation/selection implementation or creation bridge;
   required Qt/runtime providers, eager binding, visibility and NODELETE remain.
   Ensure test-only defines cannot enter it. Run existing RM2 profile/dispatch
   controls and required checks; its gate, manifest/build inputs and approved
   artifact correspondence cannot change silently. A changed RM2 artifact would
   need its own qualification, never a substituted approved digest. The existing
   approved RM2 pair stays selected; this RM1 slice must not publish a rebuilt
   RM2 candidate or regenerate its approved pins. Review any extraction-induced
   RM2 binary change explicitly before integrating it, rather than treating
   source-level dispatch equivalence as artifact correspondence.
5. **Separate native acceptance.** Actual linked RM1 startup/provider resolution,
   live Reader/metatype/lookup identity, guards, bounded historical capture and
   stock recovery require a separately reviewed trial and its real evidence.
   Missing evidence remains unsupported; no host assertion, build or static
   signature completes the nine native tasks in `tasks.md` or activates a profile.

Specification review alone authorizes no target build, SDK acquisition, tablet
contact or canonical spec sync/archive. Root accepted the exact specification
diff before separately selecting source implementation and existing-toolchain
host controls; publication/integration stays with Root. Missing target inputs
still refuse. The original logical-navigation acceptance remains unchanged.
