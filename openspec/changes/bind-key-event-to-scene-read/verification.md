## Review corrections

The production key path now uses a snapshot-only copy with no persistent document observer. Cancellation is a shared atomic revocation latch; notification, stock input, destruction and snapshot polling do not wait for an active worker borrow. Existing diagnostic observer stop semantics are unchanged. Copied key facts remain local until the selected-receiver join produces an actual attempted native submission; refusal exposes no unrelated key text, while attempted/unknown retains its facts and pinned-owner evidence.

The stronger concurrent teardown control exposed a real fixture failure on both host Qt6.4.2 (`host-key-r9.log`, ASan QtCore indirect-call fault) and ARM Qt6.10.3 (`arm-key-r4.log`, QEMU SIGSEGV). A live foreign emitter raced destruction of the short-lived QObject connection context. Qt incoming QObject teardown clears the functor tag before detaching the connection, whereas an activation may already have cached the context. Exact Qt source review supports this cause; the retained host fault disassembly is consistent with a receiver virtual-call path, without claiming an exact source-line PC. The fix uses the emitting object as context, retains scoped connection handles and explicitly disconnects them during derived teardown. The functor captures only the independent atomic latch, so ordinary in-flight disconnect cannot access the dying delivery or GUI state. The Qt6.4 test-only private overload takes a method index and converts it internally; changing it to a signal index was an earlier rejected compatibility attempt (`host-key-r7.log`). Production Qt6.10 uses the public dynamic signal/functor API.

The unchanged stronger control passes in `host-key-r10.log` with ASan/UBSan and `arm-key-r5.log` under ARM/QEMU. It holds the worker borrow while a foreign thread continuously emits; GUI polling, ordinary-key forwarding and handle destruction must all finish before the worker is released, including destruction while notification remains active. Refused receiver privacy and attempted/unknown evidence assertions also pass. Existing delivery, attachment and text regressions pass in `host-regression2-*.log`. Macro-free header compilation passes in both new fixture runs. The focused fixture is wired into the existing CI Qt step. R36 `evidence-index-r2.json` records corrected source/log hashes and exact build invocations; superseded generated fixture outputs are disposable after review, while failure logs, commands and hashes remain.

This correction still does not release typed owners, issue writer authority or establish native behavior. Private linearizable borrow closure and typed nonlast retirement remain the next implementation tasks.
