## Ordered graph and metadata edits
The core runs on PR opened/reopened/synchronize and main pushes. Its conditional PR Title job calls the reusable title workflow. That file also runs alone on edited PR metadata, so a title/body edit never emits skipped Checks contexts that could replace a failed application-check result, and never restarts the SDK build. Main skips PR Title and classifies once in Checks. Checks/Linux runs applicable structural and application controls; Checks/Windows preserves real portable staging and gates Build. Build needs both platform checks; Integration needs successful Build and consumes its exact artifact ID and trusted receipt digest. No candidate-version/uploader/result wrapper jobs. Failures/cancellations/skipped required predecessors do not admit later application stages. Docs-only events retain lightweight structure/title checks and skip Rust/application compilation and consumer execution.

Five applicable application PR jobs and four current nonpublishing main jobs are intentional: the extra real Windows qualification is irreducible with Linux-only Rust/RM1 controls. SDK unit tests execute once in Checks; Integration uses a distinct retained external consumer linked against built output. This is not a renamed second unit-suite run. Consumer probe metadata is generated at build time and receipt-bound; no source-maintained version or new SDK API is introduced. Compiler libraries remain graph/compiler-bound, and model/firmware/native qualification stays unsupported/unqualified.

## Artifact contract and tests
Update candidate_artifacts only as necessary to compile/retain a consumer probe instead of collecting/replaying every unit executable. Preserve source crate/three library inventory, receipt/manifest/source/tag/hash verification, new-directory ownership and refusal before altered execution. Use a distinct schema/field for consumer probes rather than pretending probe output is a Rust unit-test report. Keep existing refusal assertions meaningful against actual new build outputs. Focused graph controls must inspect the actual workflow using maintained expression/YAML tooling, cover docs/PR/main/edited and failure/skipped/canceled predecessors, platform ownership and artifact-ID handoff. Qualify one changed actual-source artifact composition; do not repeat unchanged broad matrices locally.

## Authority limits
This change delivers compact independently shippable candidate CI. It does not activate the old publisher, mint tags/releases, alter settings or claim successful official release/native compatibility. The later qualified Release job must consume the same verified source/version/artifacts after all required predecessors; unfinished publication is not a reason to retain redundant current CI.
