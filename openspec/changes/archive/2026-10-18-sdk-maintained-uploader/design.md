# Design

Use unmodified svenstaro/upload-release-action library source at 29e53e917877a24fad85510ded594ab3c9ca12de, rebuilt with the exact already-selected minimal build/runtime package and lock recipe. The selected helper and loopback harness are byte-identical to current Buddy main. Preserve the library, action metadata and license bytes. Fresh audit must report zero advisories for the selected full build/runtime graph, and the emitted bundle must match SHA256 379dc8bce8a264c2f2badae81199160fbd485ef118d63ade01fd2113a2e1b2bc. A failure is not permission to waive an advisory or substitute a publisher.

Existing Linux Checks performs an application-admitted upstream checkout, recipe build/audit, explicit emitted-file/provenance verification and four retained actual-Action controls. Child Action execution receives only tooling selectors and a noncredential loopback token. The loopback API observes exact-ID draft uploads, missing-only interrupted retry preserving bytes, same-name races and unmatched glob refusal. The upstream absent-ID fallback can create replacement private draft ID56; this is expected observed behavior, not an atomicity guarantee. Future release composition must require original-ID and complete retained-byte proof before finalization.

Keep publication permission, real provider execution, tag creation, tool artifact transfer to a future Release job, repository protections and official SDK distribution outside this increment. No duplicated release coordinator or version calculator is introduced. Do not revive unselected softprops/CLI/tag-first compositions.
