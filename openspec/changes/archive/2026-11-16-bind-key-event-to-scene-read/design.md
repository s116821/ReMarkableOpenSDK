# Design

`KeyDelivery` arms one actual receiver event filter. Its production acquisition callback invokes `observeInputReceiver`, then acquires the existing `ResidentSlot` owner and submits `Delivery` while the synchronous selection guard remains live. The queue receives the read before this filter forwards the triggering stock event. This is ordering within the same admitted worker, not proof that every writer is excluded or that a later clear is safe.

The filter records key, modifiers, auto-repeat, count, native codes, spontaneous flag and bounded UTF-16 event text. These fields do not identify physical versus on-screen origin. The OSK's retained Enter branch sends KeyPress with no KeyRelease, so arming cannot require a release. This layer defines no Submit grammar and never accepts, rewrites or replays an event. If admission destroys the receiver, it consumes that delivery only as Qt requires to avoid forwarding to freed memory.

The facts are staged locally across reentrant admission and published only if the joined Delivery actually attempted the native request (including an unknown result). A refused/unselected source publishes no key text or facts. The copied facts and the single Delivery form one receipt. No QKeyEvent, native Scene/document pointer or selection guard escapes into the worker callback. Snapshot-only mode performs the bounded read without attaching a persistent document Observer. The original absolute deadline and shared atomic cancellation apply throughout. Notification functors capture only the atomic latch, so foreign-thread emission and in-flight notification after disconnect cannot touch GUI state. Input, notifications, handle destruction and polling do not wait on the worker borrow mutex. Existing diagnostic Observe mode keeps its frozen-prefix stop behavior.

The first committed increment retained permanent native-owner pinning. The continuing source increment adds a distinct private snapshot retirement proof: known native return, exactly matching full job ID from the pinned same worker, read admission closed and active borrowing drained, GUI adapter frames settled and a later non-reentrant retirement turn. Exact kind27 completion occurs before Task destruction, so this proof relies on snapshot state retaining only independent copied data and closed callbacks; it does not claim the Task has been destroyed. Reuse is allowed only after existing atomic nonlast release consumes worker then document owners. Unknown, repeated/missing completion, late borrowing, last-owner and release refusals keep capacity quarantined. Generic retirement must continue refusing typed Scene requests. The source remains unenabled pending production issuer/writer/currentness/owned-range integration and actual native qualification.

`SnapshotRetirement` is constructed before selected-view admission, so its QObject/Fence construction cannot reenter a live Sample. It privately connects the pinned worker's exact `jobCompleted(qulonglong)` before submission, buffers at most 16 early IDs, and retains the original absolute deadline. The callback records both off-GUI execution and exact `QThread::currentThread()` correspondence to the pinned worker address; the latter is comparison-only, not a later native dereference. After known return and one exact completion, `closeSnapshotBorrow` acquires the native-read mutex with `try_lock` and closes admission under that same lock. Counts alone cannot drain or seal admission. Closed callbacks retain only copied data/process-resident code and become inert even when supplied an invalid late Scene.

The existing `reader_retirement::Fence` spans the complete Qt key filter/acquisition and Delivery adapters, including nested event pumping and local capture destruction. Only its later `handoffReady` permits the private `ResidentSlot::retireSnapshot` path. The path rechecks opaque generation, exact worker, callback counts, known owner state and cancellation identity before worker-then-document nonlast consumption. Any refused owner remains quarantined; the generic `retirePhysically` still rejects typed requests. A private witness survives deletion of the public handle only through completion/deadline and releases its GUI captures on a queued turn. It never appears in the native callback. Successful owner release does not mark a historical read as input-revoked; actual input revocation dominates the complete copied receipt, including a notification between outer and nested snapshot collection. Neither successful release nor historical text authorizes clearing or an edit.

Static basis: exact xochitl SHA256 `071d85beef3ef2d4cc0e11002140b27b82a2cc04a2ed740a5669f591069b77df`; SceneView key entry `0x4c80fc`, reducer `0x4c04d8`, controller key action `0x4a95f0`, Enter branch `0x4a9968`, key-job enqueue `0x4a9078` to `0x6e0814`. Accepted Scene request is `0x6d6ce4`. Retained OSK Enter at `0x2a55d8..0x2a5638` sends key `0x01000005`, modifiers zero, repeat false, count one. R36 contains separately labelled ordinary objdump evidence; retained REA exports remain their original evidence source. None is hardware qualification.
