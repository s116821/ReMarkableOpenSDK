# Design

Base main49709c78aeddf16c66effb9bd4309b8593343a1b. Copy release/stage_source.py byte-identically from selected reviewed72136ed; it uses only Python standard library and local Git. Version injection occurs only in a fresh build stage and requires clean exact source, no maintained source version, regular explicit package inputs and unchanged dependency identities. Official admission requires an existing exact local tag; final release composition separately must prove remote identity. Candidate admission sets null official tag and requires explicit allow_candidate verification; no helper creates a tag or computes a bump.

Reuse the nine non-Cargo source-admission controls and two portable controls from the same selected source. Extract the two candidate-admission controls without pulling in the separately owned maintained semantic-release composition class. Keep missing-lock and source-only verification distinct. These original owned fixtures create tags only in disposable local repositories. No production credentials/network/tag/release or actual SDK compilation occurs. Tests must state their selected scope and must not imply the unrun Cargo/cross/package/publication suites passed on this composition.

A separate standard-library staging workflow can run these bounded checks on Linux/Windows without editing the SDK consumer workflow or its paths/package/license configuration. Preserve all current runtime, manifests, consumer checks and accepted canonical/archive blobs. Capture source/package/lock/all-feature acquisition remains its author. Future actual distribution integration must qualify its actual selected source/lock/package/remote authority and cannot substitute historical full-SDK fixtures.
