## Ordered behavior
Checks (lint, unit and applicable title/path/policy validation) gate build. An upstream maintained semantic calculator may resolve a candidate read-only against the immutable intended main merge source and tag history. Building may embed that candidate only in generated output. Neither candidate resolution nor pre-release integration may mint an official tag or release.

Build emits source/version/artifact identity and the exact artifacts. Integration/package checks consume these build outputs where supported rather than rebuilding a different release. All required predecessors must succeed; failed, skipped or canceled requirements cannot authorize publication. PRs can qualify the flow without write permissions or a production publisher.

One final dedicated release job is eligible only for an application-relevant main merge event after every required predecessor passes. It revalidates exact source, candidate/tag baseline and artifact bytes before the maintained upstream tag operation; a changed candidate or moved/conflicting immutable tag refuses. It publishes the already tested assets. Serialization and exact identity checks support retry without rewriting tags, replacing retained assets or silently minting a new version. Remote protection and immutable release policy remain independently verified inputs, never inferred from a local fixture.

Existing tags/published assets are verified rather than clobbered. Failed release-job retries use the original run artifacts; an entire fresh run after tagging refuses upstream no-release instead of inventing a new version or silently rebuilding recovery assets.
