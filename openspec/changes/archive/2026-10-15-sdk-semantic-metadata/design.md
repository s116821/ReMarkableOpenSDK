# Design

Use selected72136ed python-tools.in/lock and python-semantic-release.toml unchanged: PSR10.7.0, no maintained own version fields, no build command, tags/history as authority, parse_squash_commits=false and explicit pre-1.0 settings. Reuse remote_identity.py and the seven original PythonSemanticReleaseCandidate methods without the publisher class. Only fixture environment setup drops HOME reassignment; all Git writes/pushes are confined to disposable marked fixture repositories through an explicit local URL rewrite. No SDK official tags or external release API writes.

Add actual maintained CLI --print-tag --no-tag --no-commit --no-changelog --skip-build --no-push --no-vcs-release assertions for supported conventional types (including optional scopes), docs/breaking-doc suppression, pre-1.0 behavior, unchanged refs/source and named-guidance versus executable tool input. Expected fixture tags are fixed test data, not maintained SDK versions. Preserve raw initial-docs0.0.0 and failed-local-push limitations; tool exit success alone is not release authority. Do not introduce a bump engine or source parser.

Use pinned amannn/action-semantic-pull-request on fresh API titles, optional scopes consistent with normal Conventional Commits, supported grouped type regexes, and the existing maintained dorny application predicate. Application changes cannot use docs titles; documentation-only changes skip tool qualification but retain a result. Reuse actual Action loopback GET-only fixtures, adapting only workflow references, scope policy and focused vectors. No single-commit/squash-setting mutation or production actual-message guard is selected here.

New standalone workflow installs the exact hash graph in a runner-temp venv, requires a fresh full pip-audit, and executes only these tool fixtures. It has read-only permissions, no production version/tag/publish entrypoint and no Rust installation. Existing runtime/compiler/package workflows remain untouched. PR17 fixes the inventory docs-path mismatch so current-source activation can use common supported filters; until merged, qualification remains isolated fixtures. SDK initial-release/official identity and actual successful squash admission must be resolved in the later release composition, not inferred from these checks.
