## Why

The completed native investigation demonstrated actual Reader identity, guarded
insertion, conditional adjacent target acquisition and write/reopen behavior.
The SDK still lacks the resident transport and production lifetime boundary that
allow consumers to use those mechanisms. Its synthetic observation contract also
requires revision and input-epoch facts that the native procedures do not supply.

## What Changes

- Introduce an opt-in resident protocol with bounded frames, exact runtime/request
  correspondence and explicit historical native identity/order samples.
- Connect the measured versioned native executor through an asynchronous local
  endpoint with independently checked peer identity and bounded request lifetime.
- Integrate qualified SDK operations into the existing Buddy candidate with
  journal reconciliation, fresh target acquisition and independent recovery.
- Preserve dependency-free defaults and explicit unsupported native capabilities
  until the relevant executor, lifecycle and consumer acceptance gates pass.
- Add separately typed visual-only window evidence for developer setup, without
  inventing Reader facts or granting page/write authority.

## Capabilities

### New Capabilities
- `resident-native-adapter`: versioned resident control, partial facts, mutation
  correlation and native request retirement.

### Modified Capabilities
None in the first wire-contract increment. Existing synthetic APIs remain intact.

## Impact

SDK owns the protocol, native profile and lifetime/evidence contract. Buddy owns
bindings, the durable operation journal, Supervisor orchestration and product
acceptance. Manager retains one combined Buddy artifact. The source research and
its failed trials remain preserved in the existing research branch; this change
imports only implementation needed by the shipping integration.

The exact [research handoff](https://github.com/s116821/ReMarkableOpenSDK/blob/05af65656e07c939349c9a10419ba94cd8b7457e/docs/research/native-adapter-integration-plan.md)
defines positive evidence and remaining gates. No firmware update, account sync,
replacement tablet UI, per-conversation restart or direct page-opening feature
is introduced. The first increment does not expose native dispatch.
