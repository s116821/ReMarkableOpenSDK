# Design

The existing process-resident worker/Slot and exact Scene join remain the only native ownership path. A private writer cannot accept raw QTextDocument pointers, user offsets or a public boolean claiming currentness. Product association remains the existing Buddy BindingReceipt and ledger; native facts must be joined anew to its actual document/page and live worker/root.

The pinned root role ID at SceneTextItem+0x10/+0x14 is fixed `2:0`, not persistent root identity. An owned composer range uses two specifically provisioned native LF IDs. The exclusive text interval is `[left LF position + 1, right LF position)`, preserving both separators. ID-to-position alone is insufficient because deleted IDs can collapse to a position; require bounded live position-to-ID roundtrip, LF type and order under the same joined root. Recreated-looking text never recovers old ownership. Reopen requires an admitted stable ID namespace or canonical actor mapping; the loader has an optional ID transform, so raw packed-word equality alone must not invent durable authority. Native insert action ID intervals are provision facts only after exact action completion and readback, not allocator output alone.

Writer preflight uses the already-present private document layout pointer; it refuses lazy layout creation, custom layouts and provider mismatches. The exact default QtGui layout address point is provider base+0x477cc0 with RTTI base+0x477d18 on pinned QtGui93fe582cc61673342ca49e12306d7f689860016582fa46ce135ffa280a972839. Require same document, parent and worker thread. Inspect the entire bounded plain document, including content outside the requested span: layout size can process distant objects and invoke handlers. Reuse closed native/IME/edit scopes and the retained quiet-undo/no-redo conditions. Resolve owner/range and compare live revision/exact text after all preflight getters.

Native action construction, lifetime and the first-effect call must be supported by retained target evidence before implementation. The private writer exposes no borrowed objects or synchronous consumer callback, pumps no events and queues SDK-originated edits on the same worker. Known stock direct receivers update notification/cursor/cache state; traced GUI Auto edits and key/IME mutations enqueue. Earlier fixture-added reentry is not evidence of a competing stock text writer. Actual instance/native settlement remains a separate qualification boundary.

Ordinary stock Enter is a real queued LF or formatting action after the pre-key snapshot. A later conditional clear requires a causally matched fresh post-key state and a new live comparison; never assume revision+1, suppress a mismatch or replay Enter. Product shortcut remains undecided and outside SDK policy. Durable Submit must preserve the draft whenever the genuine owned writer cannot admit its exact conditional operation.
## Selected visit producer and completion

The development composer build uses the existing MutationBackend and ResidentMutation's single owner slot/effect reservation. A combined selected-input/source callback admits the exact focused SceneView, document/page/order and native worker in one synchronous Sample. The issuer watches visit changes using atomic-only direct notification latches; borrowed source wrappers and permission closures do not escape. Its worker-only range retains the weak embedded document incarnation and two issued native LF IDs. This is a runtime capability, not a second conversation registry or restart binding.

A private writer attachment owns the closed/drained borrow mutex and copied transaction result. Its native callback returns true after any attempted stock edit, including an Unknown result, so the ordinary kind-27 branch flushes pending Scene damage. The existing full-job-ID completion witness and later non-reentrant owner retirement are reused. Mutation frames are explicitly classified as mutations. No result is published as applied solely from in-callback projection verification, and worker completion is not rendering, save or durability acknowledgement.

AwaitKey counts every actual KeyPress/InputMethod in the continuous visit, preserves the selected event's raw Qt facts and exact native draft, and forwards ordinary stock input. A later input revokes an outstanding key candidate. The copied observation precedes the selected key's stock handling; it does not authorize clearing text after forwarded Enter. Product shortcut policy and a genuine post-key observation remain separate.

The endpoint does not provide durable operation-ID deduplication. The issuer retains a bounded process-lifetime consumed-operation set and refuses repeats/exhaustion; any Unknown quarantines it. Buddy's existing resident-request journal must retain the original operation and digest and prevent restart replay. Ordinary builds do not select the composer feature. The explicit development variant is source integration for tablet qualification, not an activation or an accepted native result.

## Development AwaitKey arming diagnostic

The finite tablet trial needs an actual native wait before asking for Return. The development issuer emits one text-free `RSDK_COMPOSER_ARMED_V1` line only after installing that exact active AwaitKey and timer, while its visit is allowed and no key has been captured. The existing v4 protocol still has one terminal reply. This diagnostic is not a product API or a still-live lease.

The line binds the actual runtime, client/server nonces, sequence, operation, request digest, visit and range. Its expiry is conservative: sample explicit Linux CLOCK_MONOTONIC first, then add the floored remaining original steady-clock lease budget, with checked arithmetic. It never renews that budget. The endpoint requires its authenticated current peer and the protected runtime directory's same regular stderr inode, UID, mode0600 and single link before and after one bounded write. Short/error/interrupted writes cancel the original no-send wait without retry. The once-only latch belongs to the actual lease, so an idle wait does not consume the later distinct wait's diagnostic.

The consumer owns a separate read descriptor and fresh predispatch EOF, validates the complete bounded ASCII record against its actual SDK-prepared frame/digest, and keeps physical input quiet until validation. It then overlaps input observers before inviting typing. Stale/foreign/duplicate/malformed receipts refuse the attempt. Final historical key text, same-range post-key observation and conditional writer comparison remain independent requirements. A receipt proves only armed-at-sample with remaining budget; it cannot acknowledge a key, native effect, rendering or save.
