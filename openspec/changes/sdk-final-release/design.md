# Design

Reuse the selected 72136ed final job's maintained PSR tagger, pinned Octokit GraphQL/request Actions, existing read/download-only release adapter, exact expected-byte verifier and source-built create-only uploader. Adapt artifact selection to current immutable SDK/tool IDs and receipt/provenance outputs. Preserve the four compact application stages and their independent owners. Release's explicit !cancelled() plus direct success checks for Checks, Windows, Build and Integration avoids the known skipped-title ancestor defect.

The final stage checks out the exact successful source and verifies both retained packages before publisher execution. SDK verification uses verify mode, never integration/probe replay. Uploader verification requires independently trusted provenance before inventory parsing. Exact merged-main PR and actual-source semantic eligibility precede tagging. The unchanged upstream candidate must still match the built version. PSR mints only the final exact-source tag with no source commit/changelog/build; an existing same tag is accepted only after exact remote-source verification. Source versions are never maintained.

A maintained exact-tag GraphQL lookup discovers old drafts without scanning recent releases. Explicit absence alone permits a maintained draft-create request. Store that validated original numeric ID; use the existing adapter to download retained assets, then compare to the independently verified build manifest and select only missing names. Existing published releases are verification-only, never permission to upload or replace bytes. The qualified uploader receives overwrite/promote=false, draft/check_duplicates=true. Its returned ID and subsequent original-ID/full-byte observations must refuse the known missing-ID replacement fallback. Re-observe exact remote tag and release ID immediately before maintained draft finalization. No atomic guarantee against privileged external writers is claimed.

Only the final job receives contents:write. Source builds/audits, tool reconstruction and tests stay outside that credentialed stage. The release job installs the identical hash-locked calculator graph without repeating the already-owned full audit/test suite. Checkout credentials support the maintained Git push; no user/admin token is copied into CI. Repository immutability/protected-tag setup belongs to the owner and is not silently inferred from API success. The setting-read endpoint needs Administration(read), so it must not be added as an admin-token workaround in the pipeline.

Serialize the whole main workflow, not merely its final job, so a following candidate normally observes the previous successful tag before building. Native GitHub concurrency uses cancel-in-progress=false and queue:max, with independent groups for PR runs. GitHub documents at most100 pending entries and FIFO by waiting time rather than dispatch order; do not promise unbounded or strict commit-order delivery, invent a queue service, or retag stale artifacts. Candidate/tag conflicts refuse. Preserve known queue parser limits in local actionlint and use maintained YAML/expression checks plus actual hosted workflow validation; do not suppress diagnostics or patch the validator.

Merge of this draft activates the first real publisher. Independent source review and green PR checks do not clear owner protection/first-official gates. Retain the draft and activation hold until the coordinator explicitly approves that final production effect. No held operation, production test release or settings mutation is part of development.
